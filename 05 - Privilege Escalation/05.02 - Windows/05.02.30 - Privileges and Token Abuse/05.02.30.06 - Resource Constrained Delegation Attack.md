
## Overview

**Resource-Based Constrained Delegation**, or **RBCD**, is an Active Directory privilege escalation technique that abuses control over a computer object.

In this walkthrough, the user `L.Livingstone` has `GenericAll` over the Domain Controller object. This allows the attacker to modify the target computer’s delegation configuration and configure a controlled machine account to impersonate users to services on the Domain Controller.

Attack goal:

```text
abuse GenericAll over the Domain Controller
create a controlled machine account
configure RBCD on the target computer object
request a service ticket as Administrator
use the ticket to execute commands on the Domain Controller
obtain NT AUTHORITY\SYSTEM
```

> [!warning]
> RBCD modifies Active Directory object attributes and can lead to full compromise of the target computer. Only perform this with explicit authorization and document all changes.

# Key Concepts

## Resource-Based Constrained Delegation

RBCD allows the **resource owner** to define which principals are allowed to act on behalf of other users to that resource.

The important AD attribute is:

```text
msDS-AllowedToActOnBehalfOfOtherIdentity
```

If a controlled machine account is added to this attribute on a target computer, that machine account can request delegated service tickets to the target.

---

## S4U2Self and S4U2Proxy

The attack uses Kerberos S4U flows.

```text
S4U2Self
```

Meaning:

```text
request a service ticket to self on behalf of another user
```

```text
S4U2Proxy
```

Meaning:

```text
use the S4U2Self ticket to request a service ticket to another service
```

In this walkthrough:

```text
ATTACK$ requests a ticket impersonating Administrator
then requests access to CIFS on RESOURCEDC
```

---

## Why CIFS Is Used

Target SPN:

```text
cifs/resourcedc.resourced.local
```

Why:

```text
CIFS is used for SMB file sharing
psexec-style execution relies on SMB and service creation
a CIFS ticket can be used with impacket-psexec
```

# Step 5 – Create a New Machine Account

Use `impacket-addcomputer` to create a controlled computer account.

Command:

```bash
impacket-addcomputer resourced.local/l.livingstone -dc-ip 192.168.120.181 -hashes :19a3a7550ce8c505c2d46b5e39d6f808 -computer-name 'ATTACK$' -computer-pass 'Password123'
```

Option meanings:

| Option | Meaning |
|---|---|
| `resourced.local/l.livingstone` | Domain and user used to add the computer |
| `-dc-ip 192.168.120.181` | Domain Controller IP |
| `-hashes :<NTLM>` | Authenticate with NTLM hash |
| `-computer-name 'ATTACK$'` | New machine account name |
| `-computer-pass 'AttackerPC1!'` | Password for new machine account |

Successful output:

```text
Successfully added machine account ATTACK$ with password Password123.
```


# Cleanup Notes

RBCD attacks create and modify AD objects.

Cleanup should include:

```text
remove msDS-AllowedToActOnBehalfOfOtherIdentity modification
delete the controlled machine account
remove local /etc/hosts entry if desired
delete generated ticket files
remove uploaded SharpHound artifacts
remove BloodHound collection zip from target
remove psexec service artifacts if left behind
```

Objects and files to track:

```text
ATTACK$
Administrator.ccache
SharpHound.exe
20220110120802_BloodHound.zip
BloodHound cache .bin file
```

> [!important]
> Record the original state before modifying delegation attributes. Restore the environment after testing.

# Defensive Notes

Defenders should monitor for:

```text
new computer account creation
unexpected computer accounts ending in $
modification of msDS-AllowedToActOnBehalfOfOtherIdentity
GenericAll / WriteDACL / WriteOwner over computer objects
Kerberos S4U activity
service ticket requests for CIFS to sensitive servers
psexec-style service creation
ADMIN$ write activity
BloodHound / SharpHound collection
```

Risky conditions:

```text
high MachineAccountQuota
users with GenericAll over computers
users with WriteDACL over computers
users with WriteOwner over computers
weak delegation monitoring
Domain Controller computer objects with delegated control
```

Hardening ideas:

```text
reduce MachineAccountQuota
audit computer object permissions
monitor RBCD attribute changes
review BloodHound paths to high-value computers
limit who can modify computer objects
monitor service creation on servers
tier administrative access
```

# Key Takeaways

- RBCD abuses control over a computer object to allow a controlled principal to impersonate users to that computer.
- The key attribute is `msDS-AllowedToActOnBehalfOfOtherIdentity`.
- In this walkthrough, `L.Livingstone` had `GenericAll` over `RESOURCEDC`.
- A new machine account `ATTACK$` was created with `impacket-addcomputer`.
- `rbcd.py` configured `ATTACK$` as allowed to act on behalf of users to `RESOURCEDC`.
- `impacket-getST` requested a CIFS service ticket while impersonating `Administrator`.
- `KRB5CCNAME` pointed Impacket tools to the generated `Administrator.ccache`.
- Correct hostname resolution was required for Kerberos.
- `impacket-psexec -k -no-pass` used the ticket to obtain a SYSTEM shell.
- RBCD attacks require careful cleanup because they modify AD objects.
