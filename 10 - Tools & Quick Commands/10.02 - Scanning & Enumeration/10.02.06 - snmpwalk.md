
## Overview

`snmpwalk` is a command-line tool used to query an SNMP-enabled device and recursively enumerate values beneath a specified Object Identifier, or **OID**.

SNMP can expose a significant amount of information, including:

- Operating system and hostname
    
- Network interfaces and IP addresses
    
- Routing information
    
- Running processes
    
- Installed software
    
- Listening network services
    
- User accounts
    
- Mounted filesystems
    
- System uptime
    
- Device configuration
    
- Custom scripts and command output
    
- Credentials accidentally exposed through configuration or process arguments
    

In penetration tests and CTF environments, SNMP should be treated as a potentially high-value information-disclosure service.

> Only enumerate systems that you are authorised to test.

---

## Default SNMP Ports

|Port|Protocol|Purpose|
|---|---|---|
|`161/UDP`|UDP|SNMP queries|
|`162/UDP`|UDP|SNMP traps and notifications|

SNMP normally uses UDP, so a standard TCP-only scan may miss it.

---

# 1. Identify SNMP

## Nmap Scan

```bash
sudo nmap -sU -p 161 -sV <TARGET>
```

Example:

```bash
sudo nmap -sU -p 161 -sV 192.168.1.100
```

Useful SNMP NSE scripts:

```bash
sudo nmap -sU -p 161 \
  --script "snmp-*" \
  <TARGET>
```

A more targeted scan:

```bash
sudo nmap -sU -p 161 \
  --script snmp-info,snmp-interfaces,snmp-netstat,snmp-processes,snmp-sysdescr \
  <TARGET>
```

Save the output:

```bash
sudo nmap -sU -p 161 \
  --script "snmp-*" \
  -oA snmp-nmap \
  <TARGET>
```

# 2. SNMP Versions

The most common versions are:

|Version|Authentication|Encryption|
|---|---|---|
|SNMPv1|Community string|No|
|SNMPv2c|Community string|No|
|SNMPv3|Username and authentication options|Optional encryption|

For CTFs and older environments, SNMPv1 and SNMPv2c are the most common.

The community string acts like a shared password.

Common defaults include:

```text
public
private
community
monitor
manager
admin
```

`public` is commonly read-only.

`private` is commonly associated with read-write access, although this is not guaranteed.

# 3. Test Common Community Strings

## Test SNMPv2c

```bash
snmpwalk -v2c -c public <TARGET> 1.3.6.1.2.1.1
```

Example:

```bash
snmpwalk -v2c -c public 192.168.1.100 1.3.6.1.2.1.1
```

## Test SNMPv1

```bash
snmpwalk -v1 -c public <TARGET> 1.3.6.1.2.1.1
```

## Quick System Description Check

```bash
snmpget -v2c -c public <TARGET> 1.3.6.1.2.1.1.1.0
```

A valid response confirms:

- SNMP is reachable.
    
- The version is accepted.
    
- The community string is valid.
    
- The queried OID is accessible.

# 4. Discover Community Strings

## Using Nmap

```bash
sudo nmap -sU -p 161 \
  --script snmp-brute \
  <TARGET>
```

Specify a custom wordlist:

```bash
sudo nmap -sU -p 161 \
  --script snmp-brute \
  --script-args snmp-brute.communitiesdb=/path/to/community-strings.txt \
  <TARGET>
```

---

## Using onesixtyone

Install it if required:

```bash
sudo apt install onesixtyone
```

Test a single host:

```bash
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt <TARGET>
```

Test multiple targets:

```bash
onesixtyone -c communities.txt -i targets.txt
```

Example target file:

```text
192.168.1.10
192.168.1.20
192.168.1.30
```

Useful SecLists locations may include:

```bash
find /usr/share/seclists -iname "*snmp*" -o -iname "*community*"
```

---

## Using Hydra

Hydra may support SNMP community-string testing:

```bash
hydra -P communities.txt <TARGET> snmp
```

`onesixtyone` is generally better suited to this task.

# 5. Initial Full Walk

Once a valid community string is found, perform a complete walk:

```bash
snmpwalk -v2c -c <COMMUNITY> <TARGET>
```

Example:

```bash
snmpwalk -v2c -c public 192.168.1.100
```

Explicitly walk from the root:

```bash
snmpwalk -v2c -c public <TARGET> 1
```

Or:

```bash
snmpwalk -v2c -c public <TARGET> .1
```

Save the results:

```bash
snmpwalk -v2c -c public <TARGET> .1 | tee snmp-full.txt
```

Generate numeric OIDs:

```bash
snmpwalk -v2c -c public -On <TARGET> .1 | tee snmp-full-numeric.txt
```

Numeric output is useful when local MIB resolution is broken.

# 6. Recommended Enumeration Workflow

Use the following order during a CTF or penetration test.

## Step 1: Confirm SNMP

```bash
sudo nmap -sU -p 161 -sV <TARGET>
```

## Step 2: Identify a Community String

```bash
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt <TARGET>
```

## Step 3: Query Basic System Information

```bash
snmpwalk -v2c -c public <TARGET> 1.3.6.1.2.1.1
```

## Step 4: Perform a Full Walk

```bash
snmpwalk -v2c -c public <TARGET> .1 | tee snmp-full.txt
```

## Step 5: Enumerate High-Value OIDs Individually

Focus on:

- Processes
    
- Process arguments
    
- Listening services
    
- Interfaces
    
- IP addresses
    
- Routes
    
- Users
    
- Installed applications
    
- Mounted filesystems
    
- Storage
    
- Custom SNMP extensions
    

## Step 6: Search the Saved Output

```bash
grep -iE \
'password|passwd|credential|secret|token|key|user|admin|config|backup|script|command|extend' \
snmp-full.txt
```

## Step 7: Compare SNMP Findings Against the Port Scan

Look for:

- Services bound only to localhost
    
- Internal IP addresses
    
- Non-standard ports
    
- Hidden applications
    
- Process arguments containing credentials
    
- Hostnames and domain names
    
- Paths to configuration files
    
- Custom monitoring scripts

# 19. Net-SNMP Extend Enumeration

Net-SNMP can be configured to execute local commands or scripts through the `extend` directive.

This is especially important in CTFs because custom extension output may expose:

- Credentials
    
- Backup status
    
- Script output
    
- Internal paths
    
- Service health information
    
- Configuration data
    
- Custom administrative commands
    

## Enumerate Net-SNMP Extensions by Name

```bash
snmpwalk -v2c \
  -c public \
  -m +NET-SNMP-EXTEND-MIB \
  <TARGET> \
  NET-SNMP-EXTEND-MIB::nsExtendObjects
```

## Enumerate Using Numeric OIDs

Numeric OIDs avoid local MIB-loading problems:

```bash
snmpwalk -v2c -c public <TARGET> \
  .1.3.6.1.4.1.8072.1.3
```

Walk the extension output table:

```bash
snmpwalk -v2c -c public <TARGET> \
  .1.3.6.1.4.1.8072.1.3.2
```

Look for extension names:

```bash
snmpwalk -v2c -c public <TARGET> \
  .1.3.6.1.4.1.8072.1.3.2.1.1
```

Look for extension command output:

```bash
snmpwalk -v2c -c public <TARGET> \
  .1.3.6.1.4.1.8072.1.3.2.3
```

The exact accessible branches depend on the target configuration.

# 20. MIB Troubleshooting on Kali

## Common Symptoms

You may receive errors such as:

```text
Cannot find module (SNMPv2-SMI)
Cannot find module (SNMPv2-TC)
Did not find 'enterprises'
Cannot resolve OID
Unknown Object Identifier
```

These errors normally indicate a problem with local MIB loading rather than a problem with the remote SNMP service.

The request may fail before it is sent because Kali cannot translate the named OID.

---

## Avoid Replacing the MIB Search Path

This can cause problems:

```bash
snmpwalk -M /usr/share/snmp/mibs/ ...
```

The `-M` option sets the MIB search path. Providing only one directory may exclude other required MIB directories.

Prefer either omitting `-M` entirely:

```bash
snmpwalk -v2c \
  -c public \
  -m +NET-SNMP-EXTEND-MIB \
  <TARGET> \
  NET-SNMP-EXTEND-MIB::nsExtendObjects
```

Or append a directory using `+`:

```bash
snmpwalk -M +/path/to/mibs ...
```

---

## Install MIB Packages

Ensure the Kali repository contains:

```text
main contrib non-free non-free-firmware
```

Example repository entry:

```text
deb http://http.kali.org/kali kali-rolling main contrib non-free non-free-firmware
```

Install SNMP and the MIB downloader:

```bash
sudo apt update
sudo apt install snmp snmp-mibs-downloader
sudo download-mibs
```

---

## Enable MIB Loading

Check:

```bash
cat /etc/snmp/snmp.conf
```

If the file contains:

```text
mibs :
```

Comment it out:

```text
# mibs :
```

The original setting disables automatic MIB loading.

---

## Test MIB Translation

```bash
snmptranslate -On NET-SNMP-EXTEND-MIB::nsExtendObjects
```

Expected numeric translation:

```text
.1.3.6.1.4.1.8072.1.3.2
```

Display the MIB tree:

```bash
snmptranslate -Tp NET-SNMP-EXTEND-MIB::nsExtendObjects
```

---

## Use Numeric OIDs as a Fallback

When named MIBs fail, query the numeric OID directly:

```bash
snmpwalk -v2c -c public <TARGET> \
  .1.3.6.1.4.1.8072.1.3
```

This separates two different problems:

1. Can Kali resolve the MIB name?
    
2. Does the remote SNMP service answer the query?
    

If the numeric OID works but the named OID fails, the problem is local MIB resolution.

# 23. Fast Enumeration Script

Create a simple Bash script:

```bash
#!/usr/bin/env bash

set -u

if [[ $# -lt 2 ]]; then
    echo "Usage: $0 <target> <community> [version]"
    exit 1
fi

TARGET="$1"
COMMUNITY="$2"
VERSION="${3:-2c}"
OUTDIR="snmp-${TARGET}"

mkdir -p "$OUTDIR"

declare -A OIDS=(
    [system]="1.3.6.1.2.1.1"
    [interfaces]="1.3.6.1.2.1.2.2"
    [ip-addresses]="1.3.6.1.2.1.4.20"
    [routes]="1.3.6.1.2.1.4.21"
    [arp]="1.3.6.1.2.1.4.22"
    [tcp]="1.3.6.1.2.1.6.13"
    [udp]="1.3.6.1.2.1.7.5"
    [storage]="1.3.6.1.2.1.25.2.3"
    [processes]="1.3.6.1.2.1.25.4.2"
    [software]="1.3.6.1.2.1.25.6.3"
    [users]="1.3.6.1.4.1.77.1.2.25"
    [net-snmp-extend]="1.3.6.1.4.1.8072.1.3"
)

echo "[+] Target: $TARGET"
echo "[+] Version: $VERSION"
echo "[+] Community: $COMMUNITY"
echo "[+] Output directory: $OUTDIR"
echo

for NAME in "${!OIDS[@]}"; do
    OID="${OIDS[$NAME]}"

    echo "[+] Enumerating $NAME — $OID"

    snmpwalk \
        -v"$VERSION" \
        -c "$COMMUNITY" \
        -t 5 \
        -r 1 \
        -On \
        "$TARGET" \
        "$OID" \
        > "$OUTDIR/$NAME.txt" 2>&1
done

echo "[+] Running full walk"

snmpwalk \
    -v"$VERSION" \
    -c "$COMMUNITY" \
    -t 5 \
    -r 1 \
    -On \
    "$TARGET" \
    .1 \
    > "$OUTDIR/full-walk.txt" 2>&1

echo "[+] Searching output for high-value terms"

grep -RniE \
'password|passwd|credential|secret|token|key|admin|user|config|backup|script|command|127\.0\.0\.1' \
"$OUTDIR" \
> "$OUTDIR/interesting-findings.txt" 2>/dev/null || true

echo "[+] Enumeration complete"
echo "[+] Review: $OUTDIR/interesting-findings.txt"
```

Make it executable:

```bash
chmod +x snmp-enum.sh
```

Run it:

```bash
./snmp-enum.sh <TARGET> public
```

Example:

```bash
./snmp-enum.sh 192.168.1.100 public
```

# 25. Read-Write Community Strings

Some SNMP configurations allow values to be modified using `snmpset`.

A read-write community string represents a significantly higher risk than read-only access.

Common candidates include:

```text
private
manager
admin
write
rw
```

Confirming write access can alter the target. Do not use `snmpset` unless it is explicitly permitted within the rules of engagement.

Basic syntax:

```bash
snmpset -v2c -c <COMMUNITY> \
  <TARGET> \
  <OID> \
  <TYPE> \
  <VALUE>
```

Common data types include:

|Type|Meaning|
|---|---|
|`i`|Integer|
|`u`|Unsigned integer|
|`s`|String|
|`x`|Hex string|
|`a`|IP address|
|`o`|OID|
|`t`|Timeticks|

Example syntax only:

```bash
snmpset -v2c -c private \
  <TARGET> \
  <WRITABLE-OID> \
  s \
  "value"
```

Do not test writes against production systems without explicit authorisation.

# 26. SNMPv3 Enumeration

SNMPv3 does not use a simple community string.

Common security levels are:

|Level|Authentication|Encryption|
|---|---|---|
|`noAuthNoPriv`|No|No|
|`authNoPriv`|Yes|No|
|`authPriv`|Yes|Yes|

## noAuthNoPriv

```bash
snmpwalk -v3 \
  -l noAuthNoPriv \
  -u <USERNAME> \
  <TARGET> .1
```

## authNoPriv

```bash
snmpwalk -v3 \
  -l authNoPriv \
  -u <USERNAME> \
  -a SHA \
  -A '<AUTH-PASSWORD>' \
  <TARGET> .1
```

## authPriv

```bash
snmpwalk -v3 \
  -l authPriv \
  -u <USERNAME> \
  -a SHA \
  -A '<AUTH-PASSWORD>' \
  -x AES \
  -X '<PRIVACY-PASSWORD>' \
  <TARGET> .1
```

Algorithms depend on what the target supports.

# 27. Troubleshooting

## Timeout: No Response

Example:

```text
Timeout: No Response from <TARGET>
```

Possible causes:

- UDP/161 is filtered.
    
- The community string is incorrect.
    
- The SNMP version is incorrect.
    
- The source IP is not permitted.
    
- The service is rate-limiting requests.
    
- The target is offline.
    
- Routing or VPN connectivity is broken.
    

Try:

```bash
ping -c 3 <TARGET>
```

```bash
sudo nmap -sU -p 161 --reason <TARGET>
```

```bash
snmpwalk -v1 -c public <TARGET> 1.3.6.1.2.1.1
```

```bash
snmpwalk -v2c -c public <TARGET> 1.3.6.1.2.1.1
```

Increase timeout:

```bash
snmpwalk -t 10 -r 2 \
  -v2c -c public \
  <TARGET> .1
```

---

## Unknown Object Identifier

Example:

```text
Unknown Object Identifier
```

Use a numeric OID:

```bash
snmpwalk -v2c -c public <TARGET> \
  .1.3.6.1.4.1.8072.1.3
```

Then repair local MIB loading separately.

---

## No Such Object

Example:

```text
No Such Object available on this agent at this OID
```

This usually means:

- The target does not implement that OID.
    
- The target uses a different operating system.
    
- The community string has a restricted view.
    
- The queried MIB is unsupported.
    
- The OID is incorrect.
    

Try walking a broader parent OID.

---

## End of MIB

Example:

```text
No more variables left in this MIB View
```

This may be normal and indicates the walk has reached the end of the accessible branch.

It may also indicate that the community string is restricted to a limited SNMP view.

---

## Partial Results

If only a small subset of OIDs is visible, the SNMP server may use view-based access restrictions.

Try:

```bash
snmpwalk -v2c -c public <TARGET> .1
```

Then identify which branches are accessible.

# 30. Key Takeaways

- Always scan UDP port 161 explicitly.
    
- Test both SNMPv1 and SNMPv2c.
    
- Community strings function as shared SNMP credentials.
    
- Start with system information, then perform a full walk.
    
- Use numeric OIDs when MIB resolution fails.
    
- Do not use `-M` carelessly because it can replace the normal MIB search path.
    
- Process arguments are one of the highest-value SNMP data sources.
    
- Compare SNMP listening-port data with Nmap to identify hidden services.
    
- Network interfaces and routes may reveal internal pivoting opportunities.
    
- Net-SNMP `extend` entries may disclose custom script output or credentials.
    
- Save all results and search them systematically rather than reading the entire walk manually.
    
- Read-write SNMP access can modify target settings and should only be tested when explicitly authorised.
