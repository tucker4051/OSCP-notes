
## Overview

**DCSync** is an Active Directory credential extraction technique that abuses domain replication.

Instead of logging on to a Domain Controller and dumping credentials from disk or memory, DCSync uses the built-in **Directory Replication Service Remote Protocol** to request replicated credential data from a Domain Controller.

In effect, the attacker-controlled account asks a Domain Controller to replicate secrets, similar to how another Domain Controller would.

DCSync can retrieve credential material such as:

```text
NTLM hashes
LM hashes
Kerberos AES keys
Kerberos DES keys
password metadata
account metadata
password history
cleartext-equivalent reversible encryption data if present
```

> [!important]
> DCSync is extremely powerful because it can retrieve credential material for domain users without requiring interactive logon to the Domain Controller.

---

# Simple Mental Model

```text
Attacker-controlled account
↓
Has replication rights
↓
Requests replication data from Domain Controller
↓
Domain Controller returns credential material
↓
Attacker extracts hashes / Kerberos keys / password metadata
```

Plain English:

```text
DCSync does not steal the database file directly.
It asks the Domain Controller to replicate sensitive account data.
```

---

# Why DCSync Works

Production Active Directory domains often have multiple Domain Controllers.

Domain Controllers synchronize directory data using:

```text
Directory Replication Service
Directory Replication Service Remote Protocol
DRSR
DRSUAPI
```

This replication process is legitimate and necessary for AD to function.

The critical security point:

```text
The Domain Controller checks whether the requesting security principal has replication rights.
```

If a user or group has the required replication rights, it may be able to request sensitive replicated data.

---

# Required Rights

To perform DCSync, an account needs domain replication-related rights.

Commonly referenced rights:

```text
Replicating Directory Changes
Replicating Directory Changes All
Replicating Directory Changes in Filtered Set
```

PowerView / ACL names may appear as:

```text
DS-Replication-Get-Changes
DS-Replication-Get-Changes-All
DS-Replication-Get-Changes-In-Filtered-Set
```

The key right for secret data replication is:

```text
DS-Replication-Get-Changes-All
```

By default, these rights are commonly held by:

```text
Domain Admins
Enterprise Admins
Administrators
default domain administrator accounts
Domain Controllers
```

They may also be delegated to other users or groups.

> [!warning]
> A normal-looking domain user with replication rights is a severe misconfiguration. If compromised, that account can be used to retrieve domain credential material.

# DCSync Attack Flow

```text
1. Obtain credentials for a DCSync-capable account.
2. Authenticate to the domain using that account.
3. Request replication data from a Domain Controller.
4. Extract credential material for one or more target users.
5. Crack, reuse, or report the recovered hashes/keys.
```

Diagram:

```text
Controlled account with replication rights
        |
        | DRSUAPI / DRSGetNCChanges request
        v
Domain Controller
        |
        | Replicated credential material
        v
Attacker
```

# DCSync vs Other Credential Access Techniques

## DCSync vs LSASS Dumping

| Technique | Target | Requires |
|---|---|---|
| LSASS dumping | Credentials cached on one host | Local admin/SYSTEM on that host |
| DCSync | Domain replication data | Replication rights in AD |

Plain English:

```text
LSASS dumping extracts credentials from a machine where users have logged on.
DCSync asks the Domain Controller for replicated domain credential data.
```

DCSync can retrieve credentials for accounts that are not logged on to the attacker’s current machine.

---

## DCSync vs NTDS.dit Dumping

| Technique | Access Pattern | Notes |
|---|---|---|
| NTDS.dit dump | Copy or extract the AD database from a DC | Requires DC-level file or backup access |
| DCSync | Request replicated data over DRSUAPI | Does not require directly copying NTDS.dit |

DCSync is powerful because:

```text
it uses legitimate replication functionality
it can be performed remotely
it can target specific users
it can retrieve NTLM hashes and Kerberos keys
```

# Important Replication Rights

| Friendly Name | ACL / ObjectAceType Name | Why It Matters |
|---|---|---|
| Replicating Directory Changes | `DS-Replication-Get-Changes` | Allows replication of directory changes |
| Replicating Directory Changes All | `DS-Replication-Get-Changes-All` | Allows replication of secret data |
| Replicating Directory Changes in Filtered Set | `DS-Replication-Get-Changes-In-Filtered-Set` | Allows replication of filtered attribute set data |

> [!important]
> `DS-Replication-Get-Changes-All` is the critical right associated with replicating sensitive credential data.

DCSync may reveal cleartext-equivalent data when accounts are configured with reversible encryption.


This appears in:

```text

```

View the file:

```bash

```

Example output:

```text
proxyagent:CLEARTEXT:Pr0xy_ILFREIGHT!
```

---

## What Reversible Encryption Means

When reversible encryption is enabled on an account:

```text
the password is not stored as plain text
the password is stored using reversible encryption
the required key material can be obtained by Domain Admin-equivalent access
tools such as secretsdump can decrypt the value during NTDS extraction or DCSync
```

The source notes:

```text
passwords are stored using RC4 encryption
the key needed to decrypt them is stored in the registry as the Syskey
```

Important operational point:

```text
If reversible encryption is disabled, the user must change their password before the password is stored using normal one-way encryption.
```

Any password set while reversible encryption was enabled remains recoverable until changed.

# Troubleshooting

## Mimikatz DCSync Fails

Possible causes:

```text
current context lacks replication rights
wrong domain name
wrong username format
target DC unreachable
network filtering
Kerberos/authentication issue
AV/EDR blocking tool
```

Check:

```text
user has replication rights
domain FQDN is correct
target account format is correct
DC is reachable
time is synchronized
tool is running in the intended user context
```

---

## secretsdump Fails with Access Denied

Likely causes:

```text
account does not have required replication rights
wrong password
wrong domain
wrong DC target
account is locked or disabled
```

Validate:

```cmd
net user <user> /domain
```

or with PowerView:

```powershell
Get-NetUser <user> | select memberof
```

---

## Password Contains Special Characters

If a password contains `!`, Bash history expansion may interfere.

Use single quotes:

```bash
'PasswordWith!'
```

Or escape the exclamation mark:

```bash
PasswordWith\!
```

---

## Kerberos or Time Errors

Kerberos is time-sensitive.

If clock-related errors occur:

```text
sync time with the Domain Controller
verify timezone and clock skew
rerun command after time sync
```

---

## No Cleartext File Data

Possible reasons:

```text
no accounts have reversible encryption enabled
the target account has changed its password since reversible encryption was disabled

```

Check for reversible encryption:

```powershell
Get-ADUser -Filter 'userAccountControl -band 128' -Properties userAccountControl
```

# Key Takeaways

- DCSync abuses legitimate Active Directory replication.
- It uses DRSUAPI / Directory Replication Service behavior.
- It does not require interactive logon to a Domain Controller.
- It requires replication rights on the domain object.
- Key rights include `DS-Replication-Get-Changes`, `DS-Replication-Get-Changes-All`, and `DS-Replication-Get-Changes-In-Filtered-Set`.
- `DS-Replication-Get-Changes-All` is critical for secret replication.
- Domain Admins, Enterprise Admins, Administrators, and Domain Controllers commonly have replication rights by default.
- Misconfigured normal users may also have DCSync-capable rights.
- PowerView can confirm replication rights by checking ACLs on the domain object.
- Mimikatz can perform DCSync from Windows with `lsadump::dcsync`.
- Impacket `secretsdump` can perform DCSync from Linux.
- DCSync can retrieve NTLM hashes, LM hashes, Kerberos keys, password history, and metadata.
- `secretsdump` may also decrypt reversible encryption data into `.ntds.cleartext`.
- Hashcat mode `1000` is used for NTLM hashes.
- DCSync of `Administrator` or `krbtgt` represents severe domain compromise.
- Monitor replication requests from non-Domain Controller systems.
- Regularly audit replication rights and domain root ACLs.
