## Overview

The **ActiveDirectory PowerShell module** is a Microsoft-provided set of PowerShell cmdlets for administering and enumerating Active Directory.

It can be useful during assessments because it may already exist on administrator workstations or management hosts.

The module can enumerate:

```text
domain information
users
groups
group membership
SPN accounts
trust relationships
domain SID
domain functional level
child domains
linked GPOs
```

> [!tip]
> Using built-in Microsoft tooling can sometimes blend in more than uploading offensive tools, but activity should still be assumed detectable.

---

# When To Use

Use the ActiveDirectory module when:

```text
you have a Windows foothold
you have valid domain credentials
the host has RSAT / AD module installed
you want to avoid dropping extra tools
you need quick domain, user, group, or trust information
```

# Enumerate Domain Information

```powershell
Get-ADDomain
```

Useful fields:

| Field | Why It Matters |
|---|---|
| `DNSRoot` | Domain FQDN |
| `DomainSID` | Needed for ticket attacks and SID context |
| `DomainMode` | Domain functional level |
| `ChildDomains` | Possible child-domain paths |
| `PDCEmulator` | Key DC role |
| `RIDMaster` | Key DC role |
| `InfrastructureMaster` | Key DC role |
| `LinkedGroupPolicyObjects` | GPOs linked to domain |

Example important values:

```text
DNSRoot: INLANEFREIGHT.LOCAL
DomainSID: S-1-5-21-3842939050-3880317879-2865463114
DomainMode: Windows2016Domain
ChildDomains: LOGISTICS.INLANEFREIGHT.LOCAL
```

# Find Users with SPNs

Users with SPNs may be Kerberoastable.

```powershell
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName
```

Look for:

```text
service accounts
MSSQL accounts
backup accounts
ADFS accounts
SharePoint accounts
monitoring accounts
```

Example accounts from the source:

```text
adfs
backupagent
```

Decision:

```text
If user has SPN:
    consider Kerberoasting
```

---

# Enumerate Trust Relationships

```powershell
Get-ADTrust -Filter *
```

Useful fields:

| Field | Meaning |
|---|---|
| `Name` | Trusted domain |
| `Direction` | Inbound, outbound, bidirectional |
| `IntraForest` | Trust within same forest |
| `ForestTransitive` | Forest trust |
| `SelectiveAuthentication` | Whether selective auth is enabled |
| `SIDFilteringQuarantined` | SID filtering state |

Example trusts:

```text
LOGISTICS.INLANEFREIGHT.LOCAL
FREIGHTLOGISTICS.LOCAL
```

Decision:

```text
If trust exists:
    investigate child-to-parent paths
    investigate forest trust paths
    check trust direction
    check whether selective authentication is enabled
```

```text
Administrators

Domain Admins
```

# Get Detailed Group Information

```powershell
Get-ADGroup -Identity "Backup Operators"
```

Useful fields:

```text
DistinguishedName
GroupCategory
GroupScope
Name
SID
```

---

# Enumerate Group Members

```powershell
Get-ADGroupMember -Identity "Backup Operators"
```

Example result:

```text
SamAccountName: backupagent
```

Decision:

```text
If user is in Backup Operators:
    account may be high-value
    compromise may lead to sensitive backup/restore abuse
    investigate logon locations, credentials, and access
```

# Practical Workflow

```text
1. Check whether the module is loaded.
2. Import ActiveDirectory if needed.
3. Run Get-ADDomain.
4. Record domain SID and child domains.
5. Enumerate groups.
6. Check privileged group membership.
7. Check users with SPNs.
8. Enumerate trusts.
9. Feed findings into BloodHound or manual attack planning.
```

# Key Takeaways

- The ActiveDirectory PowerShell module is a Microsoft-native enumeration option.
- It can enumerate domain structure, users, groups, trusts, and SPN accounts.
- It is useful when offensive tools are blocked or unnecessary.
- `Get-ADDomain` gives critical domain context.
- `Get-ADUser` with `ServicePrincipalName` filtering identifies Kerberoasting targets.
- `Get-ADTrust` identifies cross-domain or cross-forest paths.
- `Get-ADGroupMember` helps identify privileged users and nested risk areas.
