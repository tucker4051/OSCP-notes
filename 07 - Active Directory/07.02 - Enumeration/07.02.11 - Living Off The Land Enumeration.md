## Overview

**Living off the land enumeration** means using native Windows and Active Directory tools already present on a host instead of uploading external tooling.

This is useful when:

```text
the host has no internet access
tool transfer is blocked
EDR blocks known tools
the client requires use of managed hosts only
you want to reduce dependency on offensive tooling
you need to enumerate with built-in commands
```

Common built-in tools and commands include:

```text
hostname
systeminfo
ipconfig
set
echo
PowerShell cmdlets
netsh
sc
qwinsta
arp
route
wmic
net
net1
dsquery
```

> [!important]
> Living off the land does not mean invisible. Native tools are often monitored, especially `powershell.exe`, `wmic.exe`, `net.exe`, and remote management commands.

---

# Scenario

Assume:

```text
you are on a managed Windows host
the host has no internet access
tool upload attempts failed
the client wants to know what enumeration is possible using native tooling
```

Goal:

```text
enumerate host state
enumerate domain context
identify reachable networks
check defenses
identify logged-on users
enumerate AD users, groups, computers, and attributes
find possible attack paths without external tools
```

---

# Why Living Off The Land Matters

External tools may create obvious telemetry:

```text
file downloads
tool execution
known tool signatures
EDR alerts
network connections to attacker infrastructure
PowerShell import events
unusual binaries on disk
```

Native commands may blend in better with admin activity, but they are still detectable.

Useful mindset:

```text
Use built-in tools to gather enough context.
Record findings.
Correlate output.
Only escalate to external tools if allowed and needed.
```

# PowerShell Native Enumeration

PowerShell is built into Windows and can enumerate host, environment, and configuration details.

## Useful PowerShell Cmdlets

| Cmdlet / Command | Purpose |
|---|---|
| `Get-Module` | Lists currently loaded modules |
| `Get-ExecutionPolicy -List` | Shows execution policy settings by scope |
| `Set-ExecutionPolicy Bypass -Scope Process` | Changes policy only for current process |
| `Get-ChildItem Env: \| ft Key,Value` | Lists environment variables |
| `Get-Content $env:APPDATA\Microsoft\Windows\Powershell\PSReadline\ConsoleHost_history.txt` | Reads PowerShell command history |

> [!warning]
> PowerShell download cradles and `IEX` are highly suspicious in real environments. Use only when explicitly authorized.

# Dsquery with LDAP Filters

## Users with PASSWD_NOTREQD

Search for users with the `PASSWD_NOTREQD` flag set:

```cmd
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=32))" -attr distinguishedName userAccountControl
```

Interpretation:

```text
userAccountControl bit 32 = PASSWD_NOTREQD
```

Decision:

```text
If users have PASSWD_NOTREQD:
    investigate account purpose
    mark as weak configuration / reporting item
    check whether account is active or privileged
```

---

## Find Domain Controllers

Search for objects with the domain controller UAC bit:

```cmd
dsquery * -filter "(userAccountControl:1.2.840.113556.1.4.803:=8192)" -limit 5 -attr sAMAccountName
```

Example output:

```text
ACADEMY-EA-DC01$
```

Interpretation:

```text
userAccountControl bit 8192 identifies domain controller computer accounts
```

---

# LDAP Filtering Refresher

## UAC Bit Matching Format

Example:

```text
userAccountControl:1.2.840.113556.1.4.803:=8192
```

Breakdown:

| Part | Meaning |
|---|---|
| `userAccountControl` | Attribute being checked |
| `1.2.840.113556.1.4.803` | LDAP matching rule OID |
| `8192` | Decimal bitmask value to match |

---

# LDAP Matching Rule OIDs

| OID | Meaning |
|---|---|
| `1.2.840.113556.1.4.803` | Bitwise AND match; bit value must match |
| `1.2.840.113556.1.4.804` | Bitwise OR match; any matching bit can satisfy filter |
| `1.2.840.113556.1.4.1941` | Recursive matching rule for DN-based membership chains |

---

# LDAP Logical Operators

LDAP filters can combine conditions.

| Operator | Meaning |
|---|---|
| `&` | AND |
| `|` | OR |
| `!` | NOT |

---

## AND Example

Search for user objects with UAC bit `64` set:

```text
(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=64))
```

Meaning:

```text
object must be a user
AND
userAccountControl bit 64 must be set
```

---

## NOT Example

Search for user objects without UAC bit `64` set:

```text
(&(objectClass=user)(!userAccountControl:1.2.840.113556.1.4.803:=64))
```

Meaning:

```text
object must be a user
AND
userAccountControl bit 64 must not be set
```

# If You Find X, Try Y

| Finding | Try Next |
|---|---|
| Domain name | Enumerate users, groups, and DCs |
| Logon server | Treat as likely DC target for LDAP/domain queries |
| Active user session | Avoid disruptive actions; note user context |
| Additional route | Investigate reachable subnet if in scope |
| ARP entries | Correlate IPs to hosts and services |
| Firewall off | Remote enumeration/lateral movement may be easier |
| Defender disabled or outdated | Report weak endpoint protection posture |
| Defender running with tamper protection | Expect tooling/payload friction |
| PowerShell history exists | Review for credentials and admin paths |
| ActiveDirectory module loaded | Use native AD PowerShell cmdlets |
| Domain Admins list | Mark users as high value |
| Password policy | Plan safe spraying thresholds |
| User with `Password expires Never` | Check for service/stale account risk |
| `PASSWD_NOTREQD` flag | Investigate weak account configuration |
| Computer object in server OU | Prioritize based on role |
| SQL/web/mail hostnames | Search for app/service credentials |
| Trust/domain shown by WMIC | Investigate cross-domain relationship |
| `net` monitored concern | `net1` may avoid weak string detections only |

## Net Commands Fail

Possible causes:

```text
not domain authenticated
domain unreachable
blocked by policy
command syntax issue
EDR interference
```

Try:

```cmd
net1 group /domain
```

Only treat this as a weak detection workaround, not real stealth.

---

## Dsquery Not Found

Possible causes:

```text
RSAT / AD DS tools not installed
not running from suitable host
insufficient context
```

Fallback:

```text
net commands
wmic LDAP namespace queries
PowerShell AD module if available
manual LDAP through available tooling
```

## PowerShell History File Missing

Possible causes:

```text
PSReadLine not used
running as SYSTEM profile
history cleared
different user profile
PowerShell version/configuration
```

Check user context:

```cmd
whoami
```

Check environment:

```powershell
Get-ChildItem Env: | ft Key,Value
```

# Defensive Notes

Living-off-the-land enumeration may still generate:

```text
PowerShell process creation
PowerShell operational logs
Script Block Logging
wmic.exe execution
net.exe execution
net1.exe execution
dsquery execution
WMI queries
LDAP queries
domain group enumeration
user enumeration
firewall queries
Defender status checks
process listing
session queries
network reconnaissance commands
```

Suspicious examples:

```cmd
net group "Domain Admins" /domain
net user /domain
wmic ntdomain list /format:list
dsquery * -filter
powershell.exe -version 2
Get-MpComputerStatus
arp -a
route print
```

Defensive controls:

```text
monitor built-in admin tool usage
baseline normal command usage by role
alert on unusual domain enumeration
monitor PowerShell logs
disable PowerShell v2 where possible
restrict unnecessary WMI access
monitor dsquery usage
monitor net/net1 enumeration
review local admin rights
review logged-on admin behavior
```

# Key Takeaways

- Living off the land uses native Windows and AD tooling.
- It is useful when external tools cannot be uploaded.
- `systeminfo` provides a quick host summary.
- Environment variables reveal domain, user, path, and profile context.
- PowerShell history may expose credentials or useful admin paths.
- `netsh`, `sc`, and `Get-MpComputerStatus` help check defenses.
- `qwinsta` helps determine whether other users are active.
- `arp -a` and `route print` reveal reachable hosts and networks.
- `wmic` can enumerate host, process, domain, user, group, and system account information.
- `net` commands can enumerate users, groups, shares, domain policy, and computers.
- `net1` may bypass simple string-based detection but is not stealthy.
- `dsquery` can enumerate AD objects and run LDAP filters.
- LDAP matching rules help search for specific UAC attributes.
- Built-in tools are still monitored in many environments.
- Correlate outputs from multiple native tools before choosing a path.
