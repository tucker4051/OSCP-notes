## Overview

**Snaffler** is a tool for finding sensitive files across accessible domain shares.

It works by:

```text
enumerating hosts in the domain
finding shares
checking readable directories
searching for files that may contain useful data
```

It is especially useful for discovering:

```text
passwords
SSH keys
configuration files
database dumps
key files
password vaults
developer artifacts
sensitive business data
```

---

# When To Use

Use Snaffler when:

```text
you have domain user context
you are on a domain-joined host or running as a domain user
you need to search many shares efficiently
manual share review would be too slow
you want reporting evidence for overly permissive shares
```

---

# Why Share Pillaging Matters

Domain shares often contain sensitive data because users store operational files there.

High-risk share contents can include:

```text
configuration files
hardcoded passwords
SSH private keys
database dumps
password vault files
VPN profiles
service account credentials
admin scripts
HR/legal/finance data
```

Even if a file does not directly lead to privilege escalation, it may still be a valid reporting issue.

# Basic Snaffler Command

```powershell
Snaffler.exe -s -d inlanefreight.local -o snaffler.log -v data
```

Alternative example from source:

```powershell
.\Snaffler.exe -d INLANEFREIGHT.LOCAL -s -v data
```

---

# Option Breakdown

| Option | Meaning |
|---|---|
| `-s` | Print results to console |
| `-d` | Domain to search |
| `-o` | Output log file |
| `-v data` | Verbosity level focused on useful data |

Recommended pattern:

```text
print to console
write to log file
review high-value hits first
```

# Example Output Types

Snaffler reports shares:

```text
[Share] {Green}(\\ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL\Department Shares)
[Share] {Green}(\\ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL\User Shares)
[Share] {Green}(\\ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL\ZZZ_archive)
```

Snaffler reports files:

```text
[File] {Red}<KeepExtExactRed|R|^\.key$|299B>(\\ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL\Department Shares\IT\Infosec\ShowReset.key)
[File] {Red}<KeepExtExactRed|R|^\.sqldump$|312B>(\\ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL\Department Shares\IT\Development\DenyRedo.sqldump)
[File] {Black}<KeepExtExactBlack|R|^\.ppk$|275B>(\\ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL\Department Shares\IT\Infosec\StopTrace.ppk)
```

# Interesting File Extensions

Prioritize files such as:

```text
.key
.ppk
.kdb
.kwallet
.keychain
.keypair
.sqldump
.mdf
.psafe3
.tblk
.config
.xml
.ps1
.bat
.vbs
.ini
.txt
```

Potential meaning:

| Extension | Possible Value |
|---|---|
| `.key` | Private key or license key |
| `.ppk` | PuTTY private key |
| `.kdb` | KeePass database |
| `.kwallet` | KDE wallet |
| `.keychain` | Keychain material |
| `.sqldump` | Database dump |
| `.mdf` | SQL Server database file |
| `.psafe3` | Password Safe database |
| `.bat` / `.ps1` | Scripts with possible credentials |
| `.config` / `.xml` | Application or service credentials |

# Snaffler Colour / Severity Idea

The source shows Snaffler using colour labels such as:

```text
Green
Black
Red
```

Practical interpretation:

```text
Red findings should usually be reviewed first.
Black findings may still be interesting.
Green shares indicate accessible shares.
```

---

# Decision Points

```text
If Snaffler finds private keys:
    copy and inspect if in scope
    check whether keys are encrypted
    identify possible target systems

If Snaffler finds database dumps:
    download and inspect offline
    look for credentials or hashes

If Snaffler finds password vault files:
    collect for cracking if authorised

If Snaffler finds admin scripts:
    search for hardcoded credentials

If Snaffler finds writable shares:
    assess risk and possible attack paths if in scope
```

# Reporting Value

Snaffler output can support findings such as:

```text
overly permissive shares
sensitive data exposure
credential storage in shares
poor secrets management
excessive access to departmental shares
```

> [!tip]
> Snaffler raw output can be useful as supplemental client evidence, especially for prioritising share cleanup.

---

# Practical Workflow

```text
1. Run Snaffler as a domain user.
2. Write output to a log file.
3. Review red findings first.
4. Review IT, Infosec, Development, Backup, and Admin paths.
5. Copy only relevant files needed for the assessment.
6. Record source paths.
7. Test recovered credentials or keys carefully.
8. Include exposure evidence in reporting.
```

# Key Takeaways

- Snaffler automates sensitive file discovery across domain shares.
- It requires domain context or a domain-joined host.
- It is excellent for finding credentials, keys, dumps, scripts, and vault files.
- It can produce a large amount of output, so log to file.
- Review red/high-value findings first.
- Share pillaging can produce both attack paths and reportable data exposure findings.
- Always record exact file paths for evidence and cleanup.
