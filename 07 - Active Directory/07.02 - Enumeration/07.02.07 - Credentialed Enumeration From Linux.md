## Overview

Credentialed enumeration from Linux means using valid domain credentials from a Linux attack host to query Active Directory.

Once we have any valid domain credential, even a low-privileged user, we can enumerate much more than we could anonymously.

Minimum useful access:

```text
cleartext domain password
NTLM hash
Kerberos ticket
SYSTEM access on a domain-joined host
```

This note focuses on Linux-based enumeration using:

```text
CrackMapExec / NetExec
SMBMap
rpcclient
Impacket
Windapsearch
BloodHound.py
```

---

# Why Credentialed Enumeration Matters

Without credentials, many AD enumeration techniques fail or return limited information.

With even one valid low-privileged domain user, we can often enumerate:

```text
domain users
domain groups
computer accounts
shares
logged-on users
sessions
password policy
SPNs
ACLs
GPOs
trusts
local admin access
WinRM access
RDP access
BloodHound attack paths
```

> [!important]
> A low-privileged domain user is often enough to map a large portion of the domain.

# General Workflow

```text
1. Validate credentials.
2. Enumerate domain users.
3. Enumerate groups.
4. Identify privileged groups.
5. Enumerate shares.
6. Search shares for interesting files.
7. Enumerate logged-on users.
8. Check where your user has local admin.
9. Enumerate via LDAP.
10. Run BloodHound.py.
11. Analyse paths and re-enumerate findings.
```

# CrackMapExec / NetExec

## Overview

CrackMapExec, now commonly replaced by NetExec, is a powerful AD assessment tool.

It supports protocols such as:

```text
SMB
MSSQL
SSH
WinRM
```

Check help:

```bash
crackmapexec -h
```

SMB help:

```bash
crackmapexec smb -h
```

> [!tip]
> Use `-h` often. CME/NetExec has many useful options and modules.

---

# CME SMB Flags to Know

| Flag | Purpose |
|---|---|
| `-u` | Username |
| `-p` | Password |
| `-H` | NTLM hash |
| `-d` | Domain |
| `--users` | Enumerate domain users |
| `--groups` | Enumerate domain groups |
| `--loggedon-users` | Enumerate logged-on users on target |
| `--shares` | Enumerate SMB shares |
| `--pass-pol` | Enumerate password policy |
| `--sessions` | Enumerate sessions |
| `--rid-brute` | RID brute force enumeration |
| `-M` | Run a module |
| `--continue-on-success` | Continue after valid credentials are found |

```text
If badPwdCount = 0:
    safer target for careful spraying
```

# RID and SID Refresher

A domain SID identifies the domain.

Example:

```text
S-1-5-21-3842939050-3880317879-2865463114
```

Each object has a RID.

Example:

```text
RID: 0x457
```

Hex `0x457` equals decimal:

```text
1111
```

Full user SID:

```text
S-1-5-21-3842939050-3880317879-2865463114-1111
```

Built-in Administrator RID:

```text
0x1f4
```

Decimal:

```text
500
```

> [!tip]
> RID `500` is always the built-in Administrator account.

---

# rpcclient – Query User by RID

```text
queryuser 0x457
```

Example output fields:

```text
User Name
Full Name
Description
Logon Time
Password last set Time
Password can change Time
Password must change Time
user_rid
group_rid
bad_password_count
logon_count
```

Useful fields:

| Field | Why It Matters |
|---|---|
| `Password last set Time` | Password age / possible weak account |
| `bad_password_count` | Spray risk |
| `logon_count` | Account activity |
| `Description` | Possible hints or role |
| `user_rid` | Object identification |

---

## rpcclient Decision Points

```text
If anonymous bind works:
    enumerate aggressively but carefully

If you get user RIDs:
    query interesting users

If description contains notes:
    inspect for credentials or role hints

If RID is 500:
    built-in Administrator

If password last set is old:
    possible weak/stale password target
```

# Impacket psexec.py

## What It Does

`psexec.py` creates a remote service and provides an interactive shell.

It works by:

```text
uploading a randomly named executable to ADMIN$
registering a service through RPC
starting the service with Service Control Manager
communicating over a named pipe
dropping into a SYSTEM shell
```

Requirement:

```text
user must have local administrator privileges on the target
```

---

## Run psexec.py

```bash
psexec.py inlanefreight.local/wley:'transporter@4'@172.16.5.125
```

Expected result:

```text
interactive shell on target
whoami shows NT AUTHORITY\SYSTEM
```

Use when:

```text
you want SYSTEM
local admin credentials are valid
SMB/ADMIN$ is available
noise is acceptable
```

---

# Impacket wmiexec.py

## What It Does

`wmiexec.py` executes commands using WMI.

Compared to `psexec.py`:

```text
does not drop a file or executable
generates fewer logs
runs as the local admin user, not SYSTEM
provides a semi-interactive shell
```

Run:

```bash
wmiexec.py inlanefreight.local/wley:'transporter@4'@172.16.5.5
```

Important behavior:

```text
Each command spawns a new cmd.exe through WMI.
```

Detection note:

```text
Event ID 4688 may show cmd.exe process creation for each command.
```

---

# psexec.py vs wmiexec.py

| Tool | Runs As | Drops File? | Notes |
|---|---|---|---|
| `psexec.py` | SYSTEM | Yes | Louder, service-based |
| `wmiexec.py` | Supplied admin user | No | Semi-interactive, often quieter |

Decision:

```text
If you need SYSTEM and can tolerate service creation:
    use psexec.py

If you want fewer file artifacts:
    use wmiexec.py

If EDR is strict:
    both may still be detected
```

# Windapsearch – Privileged Users

```bash
python3 windapsearch.py --dc-ip 172.16.5.5 -u forend@inlanefreight.local -p Klmcargo2 -PU
```

What `-PU` does:

```text
enumerates privileged users
performs recursive searches
finds nested group membership
```

This is useful because users may be privileged indirectly.

Example:

```text
User is member of Group A
Group A is nested inside Domain Admins
User is effectively privileged
```

---

## Windapsearch Decision Points

```text
If --da shows known usernames:
    correlate with hashes/passwords/sessions

If -PU shows nested privileged users:
    mark as high-value

If --user-spns returns users:
    consider Kerberoasting

If GPOs are listed:
    review for privilege or configuration paths
```

# “If You Find X, Try Y” Map

| Finding | Try Next |
|---|---|
| Valid low-priv domain creds | CME, SMBMap, Windapsearch, BloodHound.py |
| `badPwdCount` is 0 | Safer candidate for careful spraying |
| Interesting custom share | Spider with CME or SMBMap |
| Scripts/configs in shares | Search for passwords |
| `Pwn3d!` from CME | Local admin; try Impacket execution |
| Many logged-on users | Session hunting / credential dumping path |
| DA or service account logged on where you are admin | High-value host |
| User with SPN | Kerberoasting |
| Privileged nested membership | Target user/session/path |
| ADMIN$ access | Possible remote code execution |
| No Windows host access | Use BloodHound.py from Linux |
| Local admin creds | `psexec.py` or `wmiexec.py` |
| Want SYSTEM shell | `psexec.py` |
| Want fewer file artifacts | `wmiexec.py` |

## SMBMap Shows No Access

Possible reasons:

```text

wrong domain
wrong target

credentials invalid
```

Try another host:

```text

workstation
```

# Key Takeaways

- Valid domain credentials unlock much deeper AD enumeration.
- CrackMapExec/NetExec is useful for users, groups, shares, sessions, and admin checks.
- `badPwdCount` helps avoid risky password spraying targets.
- `(Pwn3d!)` indicates local admin access on a host.
- SMBMap is excellent for share permissions and recursive listings.
- `rpcclient` can enumerate users and RIDs through MS-RPC.
- Impacket provides remote execution tools when credentials have local admin rights.
- `psexec.py` gives SYSTEM but drops a service binary.
- `wmiexec.py` is semi-interactive and does not drop an executable.
- Windapsearch is useful for LDAP enumeration from Linux.
- `-PU` in Windapsearch helps identify nested privileged users.
- BloodHound.py collects AD graph data from Linux using valid credentials.
- BloodHound path queries can reveal escalation paths missed manually.
- Always correlate tool output instead of relying on one tool.
