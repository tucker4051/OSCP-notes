## Overview

**SharpHound** is the data collector for BloodHound.

**BloodHound** is the graph-based Active Directory analysis tool used to visualize relationships and identify attack paths.

Together, they help map relationships involving:

```text
users
groups
computers
sessions
local admin rights
ACLs
GPO links
SPNs
domain trusts
remote access rights
RDP rights
WinRM rights
DCOM rights
certificate services relationships
paths to high-value targets
object properties
```

Simple flow:

```text
SharpHound
↓
Collect AD data
↓
ZIP / JSON output
↓
BloodHound
↓
Graph analysis
↓
Attack path discovery
```

BloodHound is useful because it can reveal relationships and paths that are difficult to find manually.

> [!important]
> BloodHound is most useful when combined with manual enumeration. Manual enumeration gives context; BloodHound helps visualize relationships that are easy to miss.

---

# Tool Roles

| Tool | Role |
|---|---|
| `SharpHound.exe` | Windows collector that gathers AD relationship data |
| `SharpHound.ps1` | PowerShell collector exposing `Invoke-BloodHound` |
| `BloodHound GUI / CE` | Visualizes and analyzes collected data |
| `Neo4j` | Graph database backend used by BloodHound |

# Why Use BloodHound

Manual enumeration can answer questions like:

```text
Who are the Domain Admins?
Which computers exist?
Where do I have local admin?
Which users are logged on?
Which groups are nested?
Which objects have dangerous ACLs?
```

BloodHound helps answer relationship questions:

```text
How does this user reach Domain Admin?
Which path is shortest?
Which host should I prioritize?
Which user sessions matter?
Which ACLs create escalation paths?
Which owned principals create new routes?
Which trust paths are relevant?
Which hosts have excessive local admin rights?
```

Example manual finding:

```text
stephanie has local admin on CLIENT74.
jeffadmin has a session on CLIENT74.
jeffadmin is a Domain Admin.
```

BloodHound can show this as a graph:

```text
stephanie
  └── AdminTo
      └── CLIENT74
          └── HasSession
              └── jeffadmin
                  └── MemberOf
                      └── Domain Admins
```

# When To Use

Use SharpHound / BloodHound when:

```text
you have valid domain credentials
you need to understand domain relationships
manual enumeration is becoming complex
you want attack path visualization
you need to identify local admin, session, ACL, GPO, or trust paths
you want to correlate findings from PowerView, LDAP, SMB, and session enumeration
you need reporting evidence for misconfigurations
```

> [!warning]
> BloodHound collection is highly valuable but may generate alerts in mature environments.

# Collection Strategy

## Snapshot Collection

A snapshot collection captures the domain at one point in time.

Use it to gather:

```text
users
groups
computers
ACLs
GPOs
SPNs
trusts
local admin relationships
sessions visible at collection time
```

Older PowerShell-style example:

```powershell
Invoke-BloodHound -CollectionMethod All
```

Executable-style example:

```powershell
.\SharpHound.exe --CollectionMethods All
```

Snapshot collections are useful for:

```text
initial domain mapping
identifying obvious attack paths
importing into BloodHound for graph analysis
```

---

## Loop Collection

Loop collection repeatedly collects selected data over time.

This is especially useful for session data because users log on and off throughout the day.

Example:

```powershell
.\SharpHound.exe --CollectionMethods Session --Loop
```

With duration:

```powershell
.\SharpHound.exe --CollectionMethods Session --Loop --LoopDuration 02:00:00
```

Why loop sessions?

```text
privileged users may log on after your first snapshot
server admins may only appear briefly
help desk users may move between machines
short-lived sessions can create important attack paths
```

Use loop collection when:

```text
the engagement allows it
you need better session coverage
you are waiting for privileged user activity
you want to enrich an initial BloodHound graph
```

# Collection Method Overview

Common SharpHound collection methods:

| Method | Purpose |
|---|---|
| `Default` | Common baseline collection |
| `All` | Broad collection of most available data |
| `Group` | Security group memberships |
| `ACL` | Abusable AD object permissions |
| `Trusts` | Domain trust relationships |
| `Container` | OU tree and GPO links |
| `LocalAdmin` | Local Administrators group membership |
| `RDP` | Remote Desktop Users group membership |
| `DCOM` | Distributed COM Users membership |
| `PSRemote` | Remote Management / PowerShell Remoting membership |
| `Session` | User session collection |
| `LoggedOn` | Privileged logged-on collection method |
| `ObjectProps` | Useful object properties such as timestamps |
| `SPNTargets` | SPN target relationships |
| `DCOnly` | Domain-controller-only collection |
| `ComputerOnly` | Computer-focused collection |

> [!tip]
> `All` is useful in labs. In real assessments, choose collection methods based on scope, stealth, timing, and detection risk.

# BloodHound Core Concepts

## Nodes

Nodes are objects in the graph.

Examples:

```text
users
groups
computers
domains
OUs
GPOs
certificate authorities
sessions
```

Example nodes:

```text
STEPHANIE@CORP.COM
CLIENT74.CORP.COM
DOMAIN ADMINS@CORP.COM
JEFFADMIN@CORP.COM
```

---

## Edges

Edges are relationships between nodes.

Examples:

```text
MemberOf
AdminTo
HasSession
CanRDP
CanPSRemote
GenericAll
GenericWrite
WriteDacl
WriteOwner
Owns
AddMember
ForceChangePassword
Contains
GpLink
```

Edges answer:

```text
How are these objects connected?
What can this principal do?
What path exists from current access to target access?
```

---

## Paths

A path is a chain of nodes and edges.

Example:

```text
STEPHANIE@CORP.COM
  └── AdminTo
      └── CLIENT74.CORP.COM
          └── HasSession
              └── JEFFADMIN@CORP.COM
                  └── MemberOf
                      └── DOMAIN ADMINS@CORP.COM
```

Interpretation:

```text
stephanie can administer CLIENT74.
jeffadmin has a session on CLIENT74.
jeffadmin is a Domain Admin.
CLIENT74 is a high-value target.
```

# Marking Owned Principals

Owned principals represent objects you control.

Mark objects as owned when you have:

```text
valid credentials
interactive shell
local admin access
control over a computer
control over a user
control over a group
reliable ability to execute as that principal
accounts with recovered passwords
accounts with hashes or tickets
```

Examples:

```text
stephanie user
CLIENT75 computer
a compromised service account
a controlled workstation
```

Older UI:

```text
Right-click node
↓
Mark User as Owned
```

or:

```text
Right-click node
↓
Mark Computer as Owned
```

Current UI may use:

```text
node details
object menu
mark as owned / owned toggle
```

> [!important]
> Mark every object you genuinely control. BloodHound pathfinding is much more useful when owned principals are accurate.

```text
stephanie

CLIENT75
```

```text
                  └── HasSession
```

# High-Value Query List

Use these early after importing data.

## 1. Find All Domain Admins

Purpose:

```text
Identify high-value users.
```

Look for:

```text
Administrator
named admin accounts
service accounts in Domain Admins
nested Domain Admin membership
```

Use when:

```text
you need to know who to session-hunt
you need to identify privileged accounts
you need reporting evidence for excess DA membership
```

---

## 2. Find Shortest Paths to Domain Admins

Purpose:

```text
Find possible routes to Domain Admins from broader domain relationships.
```

Look for paths involving:

```text
AdminTo
HasSession
GenericAll
GenericWrite
WriteDacl
ForceChangePassword
CanRDP
CanPSRemote
nested groups
GPO control
```

Use this as a high-level path discovery query.

---

## 3. Find Shortest Paths from Owned Principals

Purpose:

```text
Find attack paths starting from objects you control.
```

Requires:

```text
owned users/computers marked correctly
```

This is usually more useful than broad shortest-path queries because it starts from your real access.

---

## 4. Find Principals with DCSync Rights

Purpose:

```text
Identify users or groups that can replicate domain secrets.
```

Look for edges such as:

```text
GetChanges
GetChangesAll
GetChangesInFilteredSet
DCSync
```

Decision:

```text
If an owned or reachable principal has DCSync:
    validate carefully
    DCSync may lead to domain credential extraction
```

---

## 5. Find Kerberoastable Users

Purpose:

```text
Identify users with SPNs.
```

Decision:

```text
If user has SPN:
    Kerberoast if in scope
    prioritize service accounts with weak password indicators
```

Cross-check manually:

```powershell
Get-DomainUser -SPN -Properties samaccountname,ServicePrincipalName
```

---

## 6. Find AS-REP Roastable Users

Purpose:

```text
Identify users with Kerberos pre-authentication disabled.
```

Decision:

```text
If user is AS-REP roastable:
    request AS-REP hash
    crack offline
```

Cross-check manually:

```powershell
Get-DomainUser -PreauthNotRequired
```

---

## 7. Find Computers where Domain Users are Local Admin

Purpose:

```text
Identify excessive local administrator rights.
```

Decision:

```text
If Domain Users are local admin on a host:
    any compromised domain user may access that host
    credential dumping may be possible
    report excessive local admin rights
```

---

## 8. Find Computers with Unsupported Operating Systems

Purpose:

```text
Identify legacy systems that may introduce risk.
```

Example systems:

```text
Windows 7
Windows Server 2008
```

Decision:

```text
If legacy hosts are live:
    assess carefully
    confirm with client before risky testing
    document as high-risk or legacy OS finding

If legacy hosts are stale AD objects:
    document as cleanup recommendation
```

> [!warning]
> Legacy systems may be fragile and may run critical applications. Validate before attacking.

---

Purpose:


Use for:

```text
admin session hunting
```



# Attack Path Decision Points

```text
If path shows AdminTo:
    validate local admin access manually

If path shows HasSession:
    check if you can reach and administer that host

If path shows GenericAll:
    investigate full-control abuse based on target object type

If path shows GenericWrite:
    investigate attribute modification or targeted roasting paths

If path shows WriteDacl:
    investigate granting yourself stronger rights

If path shows WriteOwner:
    investigate ownership takeover then DACL modification

If path shows ForceChangePassword:
    consider password reset impact and ROE

If path shows AddMember:
    investigate adding controlled user to target group

If path shows CanRDP:
    test RDP access

If path shows CanPSRemote:
    test WinRM / PowerShell Remoting

If path shows DCSync:
    validate replication rights carefully

If path shows Kerberoastable:
    perform Kerberoasting if in scope

If path shows AS-REP roastable:
    perform AS-REP Roasting if in scope

If path shows unsupported OS:
    validate host is live before reporting or testing
```

# Important Edge Types

## MemberOf

Meaning:

```text
User, group, or computer is a member of another group.
```

Example:

```text
jeffadmin MemberOf Domain Admins
```

Impact:

```text
jeffadmin inherits Domain Admin privileges.
```

---

## AdminTo

Meaning:

```text
A principal has local administrator rights on a computer.
```

Example:

```text
stephanie AdminTo CLIENT74
```

Impact:

```text
stephanie may be able to execute code on CLIENT74 or access admin-only resources.
```

---

## HasSession

Meaning:

```text
A user has a session on a computer.
```

Example:

```text
CLIENT74 HasSession jeffadmin
```

Impact:

```text
Credential material for jeffadmin may exist on CLIENT74.
```

---

## GenericAll

Meaning:

```text
Full control over the target object.
```

Possible impact:

```text
take over user
modify group membership
change attributes
abuse object depending on target type
```

---

## GenericWrite

Meaning:

```text
Can write certain attributes on the target object.
```

Possible impact:

```text
modify SPNs
modify logon scripts
change object attributes
create follow-on abuse paths
```

---

## WriteDacl

Meaning:

```text
Can modify the target object's ACL.
```

Possible impact:

```text
grant yourself stronger rights
create persistence
escalate privileges
```

---

## WriteOwner

Meaning:

```text
Can change ownership of the object.
```

Possible impact:

```text
take ownership
modify DACL
grant yourself control
```

---

## ForceChangePassword

Meaning:

```text
Can reset a user's password.
```

# Common BloodHound Findings and Interpretation

| Finding | Meaning |
|---|---|
| `stephanie AdminTo CLIENT74` | Stephanie has local admin on CLIENT74 |
| `CLIENT74 HasSession jeffadmin` | Jeffadmin may have credential material on CLIENT74 |
| `jeffadmin MemberOf Domain Admins` | Jeffadmin is a Domain Admin |
| `GenericAll` edge to user | Source may be able to take over target user |
| `GenericAll` edge to group | Source may fully control group membership |
| `GenericWrite` edge | Source may modify useful object attributes |
| `WriteDacl` edge | Source may grant themselves stronger rights |
| `WriteOwner` edge | Source may take ownership then modify DACL |
| `ForceChangePassword` edge to user | Source may reset target user password |
| `CanRDP` edge to computer | Source can log in via RDP |
| `CanPSRemote` edge to computer | Source can use WinRM / PowerShell Remoting |
| `DCSync` rights | Source may replicate domain secrets |
| No path from owned principals | Owned nodes may be missing or collection may be incomplete |

# Key Takeaways

- SharpHound collects Active Directory data for BloodHound.
- BloodHound visualizes AD relationships as nodes and edges.
- BloodHound can reveal attack paths missed during manual enumeration.
- Modern Kali commonly starts BloodHound with `sudo bloodhound-start`.
- SharpHound uses techniques similar to PowerView, LDAP queries, Windows APIs, and Remote Registry.
- Collection quality determines graph quality.
- `All` collection is useful in labs, but can be noisy.
- Session data is time-sensitive and may require loop collection.
- Mark owned principals before running owned-principal pathfinding.
- Run shortest-path queries from owned principals early.
- Inspect edges carefully; edges explain why a path exists.
- Validate important BloodHound paths manually.
- Unsupported OS findings should be validated before reporting.
- Local admin paths can lead to lateral movement and credential access.
- DCSync, ACL abuse, RDP, WinRM, DCOM, Kerberoastable, and AS-REP roastable queries are high-value.
- Older BloodHound labs may reference Neo4j and the desktop app.
- BloodHound CE uses a web-style workflow and file ingest through the UI/API.
- BloodHound is a decision-support tool, not a substitute for operator judgment.
- Re-run collection after every new credential, host, or privilege change.
