
## Overview

LDAP enumeration is used to query Active Directory for domain metadata, users, groups, computers, and attributes that may expose useful information.

In this walkthrough, LDAP enumeration revealed:

```text
domain naming context
hostname
domain users
usernames
description fields
credentials stored in a user description
```

The discovered credentials were later used to authenticate to SMB and WebDAV.

> [!important]
> User attributes such as `description` can contain sensitive information, including passwords. Always review LDAP attributes carefully during AD enumeration.

# Identifying a Domain Controller

The walkthrough treats the host as a Domain Controller because several common AD/DC services appear together:

```text
53/tcp    DNS
88/tcp    Kerberos
389/tcp   LDAP
445/tcp   SMB
464/tcp   kpasswd
3268/tcp  Global Catalog
5985/tcp  WinRM
```

Reasoning:

| Port | Service | Why It Matters |
|---|---|---|
| `53` | DNS | Domain Controllers often provide domain DNS |
| `88` | Kerberos | Core Windows domain authentication |
| `389` | LDAP | AD directory queries |
| `636` | LDAPS | LDAP over TLS |
| `3268` | Global Catalog | Forest-wide LDAP queries |
| `3269` | Global Catalog LDAPS | Secure Global Catalog |
| `445` | SMB | File sharing, SYSVOL, NETLOGON |
| `5985` | WinRM | Remote PowerShell access if credentials work |

# Root DSE Enumeration

## What Root DSE Is

The **Root DSE** is a special LDAP entry that exposes server metadata.

It can reveal information such as:

```text
naming contexts
domain naming context
configuration naming context
schema naming context
server hostname
supported LDAP capabilities
```

The walkthrough focuses on:

```text
namingcontexts
dnsHostName
```

---

## Query Root DSE

```bash
ldapsearch -x -H ldap://192.168.201.122 -s base
```

Flag meanings:

| Flag | Purpose |
|---|---|
| `-x` | Use simple authentication |
| `-H` | Specify LDAP URI |
| `-s base` | Query only the base object |

Interpretation:

```text
This queries the Root DSE and returns available server metadata.
```

# Base DN Enumeration

Once the base DN is known:

```text
dc=hutch,dc=offsec
```

LDAP queries can target the domain naming context.

General pattern:

```bash
ldapsearch -x -H ldap://<target> -b "<base_dn>" "<ldap_filter>"
```

Example:

```bash
ldapsearch -x -H ldap://192.168.201.122 -b "dc=hutch,dc=offsec" "(objectClass=user)"
```

# LDAP Enumeration Workflow

```text
1. Identify LDAP from port scan.
2. Confirm domain name from Nmap if available.
3. Query Root DSE.
4. Extract naming contexts.
5. Extract hostname.
6. Build base DN.
7. Add hostname/FQDN to hosts file if needed.
8. Query user objects.
9. Focus on sAMAccountName and description.
10. Review descriptions for credentials or sensitive data.
11. Build username list.
12. Test discovered credentials against exposed services.
13. Password spray carefully if appropriate.
14. Continue enumeration with validated credentials.
```

```text

```


# Troubleshooting

## LDAP Query Returns Too Much Data

Use attribute selection:

```bash
ldapsearch -x -H ldap://192.168.201.122 -b "dc=hutch,dc=offsec" "(objectClass=user)" sAMAccountName description
```

---

## Base DN Unknown

Query Root DSE:

```bash
ldapsearch -x -H ldap://192.168.201.122 -s base namingcontexts
```

---

## Hostname or Kerberos Issues

Add hostnames to `/etc/hosts`:

```text
192.168.201.122 hutchdc hutchdc.hutch.offsec
```

---

## Credentials Work on One Service but Not Another

This is normal.

Check each exposed service separately:

```text
SMB
WinRM
WebDAV
LDAP
RDP if present
SSH if present
```

Possible reasons:

```text
user lacks remote logon rights
service-specific permissions
group membership restrictions
authentication method differences
```

Report LDAP credential exposure with:

```text
affected account
attribute containing credential
cleartext value found
where it was discovered
services where it was valid
impact of credential reuse
recommended remediation
```

Example:

```text
Account:
fmcsorley

Attribute:
description

Exposed value:
CrabSharkJellyfish192

Validated against:
SMB
WebDAV
```

Recommended remediation:

```text
remove secrets from AD attributes
rotate exposed password
review all user description fields
monitor for sensitive data in LDAP attributes
restrict anonymous LDAP where appropriate
educate admins not to store credentials in user fields
```

# Key Takeaways

- LDAP enumeration can reveal domain metadata and user attributes.
- Root DSE is useful for finding the base DN and server metadata.
- `namingcontexts` identified the base DN `dc=hutch,dc=offsec`.
- `dnsHostName` helped identify `hutchdc`.
- User enumeration with `(objectClass=user)` returned useful account data.
- Focusing on `sAMAccountName` and `description` quickly exposed credentials.
- The `fmcsorley` password was found in the description field.
- WinRM authentication failed, but the same credentials worked for SMB and WebDAV testing.
- LDAP-discovered credentials can unlock further service enumeration.
- Passwords in AD attributes are high-impact findings.
